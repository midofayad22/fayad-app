Project: Pricing Cards and Best Practices

A responsive pricing cards page, with a common mistake to avoid: dynamic class names.

Open the interactive lesson (editor + quiz + progress)The exercise, quiz and progress tracking run on the interactive page.

The Project

We build three cards: Basic, Professional (featured), and Enterprise. A grid gap-6 md:grid-cols-3 grid, the featured card with a ring-2 ring, buttons with hover and focus states, and dark mode support.

Avoid Dynamic Names

Tailwind looks for complete class names as text in your files. So the code `bg-${color}-500` will generate nothing. Instead, write the full names or map them: { red: "bg-red-500", blue: "bg-blue-500" }.

Review Checklist

  • A consistent class order (for example by adding the Prettier plugin).
  • Use @theme for repeated values.
  • Test contrast, dark mode, and focus.
  • Add a real build for production instead of the browser build.

Write class names in full in your code and don't build them by concatenating strings.

Understanding the code

The grid becomes a single column on phones and three columns from md. The featured card stands out with a ring and a larger shadow. Try converting it to dark mode by adding dark: to each color.

Try it yourself

Edit and try

Add <code>dark:bg-slate-800 dark:text-white</code> to the cards and make a complete dark version.
