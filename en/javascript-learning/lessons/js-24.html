Fetch API

Learn how to use the Fetch API to send HTTP requests and get data from a Server or API.

Open the interactive lesson (editor + quiz + progress)The exercise, quiz and progress tracking run on the interactive page.

Code example

JavaScript code

fetch("https://example.com/data")
.then(response => response.json())
.then(data => {
console.log(data);
})
.catch(error => {
console.error(error);
});

Understanding the code

The Fetch API provides a modern way to send HTTP Requests from JavaScript.

It can be used to fetch data from an API or Server.

The initial result is a Response, which can be converted to JSON using response.json().

The result is usually handled with Promises or async/await.

    Correct answer: Converts the Response into usable JSON data

  3. Is fetch() related to networking?

    • Yes

    • Only with Arrays
    Answer and explanation

    Correct answer: Yes

  4. What is the problem in this code? const data = fetch(url).json();

    • fetch returns a promise that has no json(); you must await fetch and then call json() on the response
    • json() works only with POST
    • new must be added before fetch
    • url must be an object, not a string
    Answer and explanation

    Correct answer: fetch returns a promise that has no json(); you must await fetch and then call json() on the response

    fetch returns a Promise, not the response itself, so calling json() on it throws a TypeError. Write const res = await fetch(url); const data = await res.json().

  5. The server answers a fetch request with status 404. What happens to the promise?

    • It rejects and goes to catch automatically
    • It fulfills normally and we check response.ok to detect the error
    • It stays pending forever
    • The request is retried automatically
    Answer and explanation

    Correct answer: It fulfills normally and we check response.ok to detect the error

    fetch rejects only on a network failure; HTTP statuses such as 404 and 500 arrive as a normal response. So we check response.ok or status and throw the error ourselves.
