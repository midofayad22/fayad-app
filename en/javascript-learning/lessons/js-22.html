Asynchronous JavaScript

Learn the concept of Asynchronous JavaScript and how to handle tasks that take time.

Open the interactive lesson (editor + quiz + progress)The exercise, quiz and progress tracking run on the interactive page.

Code example

JavaScript code

document.getElementById("jsResult").textContent =
"Start";
setTimeout(() => {
document.getElementById("jsResult").textContent =
"Task completed";
}, 1000);

Understanding the code

Asynchronous JavaScript lets a program handle tasks that do not finish immediately.

Examples include requesting data from a Server or waiting using a Timer.

setTimeout() lets you delay running a Function for a specified time.

The goal is to handle tasks that need time without freezing the user experience.

  1. What does Asynchronous mean?

    • Running tasks in a way that does not require waiting for everything before continuing
    • Stopping the program
    • Deleting HTML
    • Changing CSS
    Answer and explanation

    Correct answer: Running tasks in a way that does not require waiting for everything before continuing

  2. Which Function is used to delay execution?

    • setTimeout()
    • delayCode()
    • waitJS()
    • pauseScript()
    Answer and explanation

    Correct answer: setTimeout()

  3. Where is Async JavaScript often needed?

    • Network requests and operations that take time
    • Only writing CSS
    • Only writing HTML
    • Only changing fonts
    Answer and explanation

    Correct answer: Network requests and operations that take time

  4. What is the print order? console.log(1); setTimeout(() => console.log(2), 0); console.log(3);

    • 1, 2, 3
    • 2, 1, 3
    • 1, 3, 2
    • 3, 2, 1
    Answer and explanation

    Correct answer: 1, 3, 2

    setTimeout defers its callback until the synchronous code finishes, even with a delay of zero. So 1 and 3 print first, then 2.

  5. A setTimeout with a 100ms delay is scheduled, then one with a 0ms delay. Which runs first?

    • The first, because it was scheduled first
    • The second, because its wait is shorter
    • They run together at the same moment
    • The program pauses 100ms then both run
    Answer and explanation

    Correct answer: The second, because its wait is shorter

    Order is decided by when each timer expires, not by the order written, and waiting does not block the rest of the program. So the 0ms timer runs first.
