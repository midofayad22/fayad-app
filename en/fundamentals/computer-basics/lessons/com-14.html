How Does a Program Work?

Learning objectives

  • Explain how Source Code becomes Machine Code and tell compiled languages from interpreted ones.
  • Follow a program's journey from storage to RAM and then to the processor.
  • Distinguish a Program from a Process and understand the role of a Library and shared libraries.

Prerequisites

  • The CPU (com-04), RAM (com-05), operating-system (com-10) and binary (com-12) lessons.

Introduction: from idea to numbers

A Program is an ordered set of instructions telling the computer what to do. But the processor understands neither Python nor Java; it understands only its own Instruction Set, a collection of binary numbers meaning things like “add”, “move” or “jump”. These numbers are Machine Code. Since writing them by hand is laborious, programmers write in a human-friendly language and have it translated.

The first block is C source; the second is its counterpart in Assembly, a readable form of machine instructions (it differs between processor families). Each Assembly line corresponds to roughly one numeric instruction.

Translation: compiled or interpreted?

There are two main ways to translate. A Compiler translates the whole program in advance into an executable file that then runs fast without needing the source, as in C, C++, Rust and Go. An Interpreter reads the program and executes it while it runs, command by command or through an intermediate step, as in Python and JavaScript; it is easier to experiment with and usually slower.

Between the two sit hybrids: Java and C# compile to Bytecode, an intermediate code that runs on a virtual machine, and modern engines use JIT compilation, converting frequently used parts into machine code while running to speed them up. So “compiled” versus “interpreted” describes less the language itself and more how it is executed.

From drive to processor

The executable on the drive is inert data and does nothing. When you double-click its icon, the operating system's Loader reads it and loads its parts into RAM, because the processor does not execute straight from the slow drive. The system then sets a pointer called the Program Counter to the first instruction, and the processor begins the Fetch-Decode-Execute cycle: fetch the instruction from memory, decode it to learn what is asked, then execute it, repeating billions of times per second.

Program versus process, and libraries

A program is a file on the drive, while a Process is that program while it runs: it has an identifier PID, its own memory space and a state. Launch the browser twice and you get two processes from one program, each with its own separate data. The operating system switches the processor among processes so fast that they appear to run together.

Nobody writes everything alone. A Library is ready-made code for common jobs such as drawing, networking or reading files. Some libraries are built into the executable (static linking); others are shared and loaded at run time (.dll files on Windows, .so on Linux), so several programs use one copy in memory. Programs ask the system for services such as opening a file through a System Call, the controlled doorway into the kernel.

Real-world applications

  • Task Manager: shows processes and their CPU and memory use, and lets you end a frozen program.
  • Updates: updating one shared library fixes a flaw in several programs at once.
  • Choosing a language: operating systems and games are often written in compiled languages, while websites and automation scripts use interpreted ones.

Common mistakes

  • “A program runs straight from the drive”: it is loaded into memory first and then executed by the processor.
  • “A language is inherently compiled or interpreted”: many languages have implementations of both kinds or a mix.
  • “Program and process are the same thing”: one program can yield several processes.
  • “An executable runs on any device”: it is tied to an operating system and a processor type.
Exercise Calculation: a 3 GHz processor executes one instruction per cycle. How many instructions per second, and how long does a 6-billion-instruction program take?
Show solution

3 GHz means 3,000,000,000 cycles per second, so it executes 3 billion instructions per second. A 6-billion-instruction program needs 6,000,000,000 ÷ 3,000,000,000 = 2 seconds. That is a theoretical minimum; real processors can execute more than one instruction per cycle but also wait for memory at times, so the figure differs.

Exercise Reasoning: why does a large program open slowly the first time and faster the next?
Show solution

The first time, the operating system reads the program's files and libraries from the drive into memory, which is the slowest step. The system keeps copies of what it read in a cache in spare RAM, so when you reopen the program soon after, it finds the files in memory and skips the drive read. With an HDD the difference is clearer, as its access is much slower than RAM.

Exercise Hands-on: watch the processes on your machine, create a new one and track it.
Show solution

Open Task Manager on Windows with Ctrl+Shift+Esc, or the terminal on Linux and start the top command. Note the PID of a program such as the browser. Then start a second instance and watch new processes appear with different PIDs and different memory. Close one instance and confirm the other keeps running, which shows they are independent processes of one program.

Summary

  • The processor runs only machine code, and every other language is translated or interpreted into it.
  • A compiler converts ahead of time, an interpreter executes while running, and hybrids exist such as bytecode and JIT.
  • A program is loaded from the drive into RAM, then the CPU fetches and executes its instructions.
  • A process is a program in action, and libraries reuse code.

    The file on disk is inert data; the loader copies it into memory and then the program counter starts.
