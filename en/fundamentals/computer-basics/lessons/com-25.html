File Systems

Learning objectives

  • Explain what a file system does between the application and the disk.
  • Know the concepts of inode, directory and path.
  • Compare NTFS, ext4, FAT32 and APFS.

Prerequisites

  • The storage lesson (com-06) and the files and folders lesson (com-11).

A disk knows nothing about files

A disk is only a numbered array of blocks. A file system is the layer that organises those blocks into names, folders, sizes, permissions and dates, and tracks which blocks are free or used.

The name is not part of the file itself; it is stored in the directory, which maps a name to an inode number. That is why one file can have several names (hard links) and why renaming does not copy the content.

What happens when you save a file?

Common types

File systemUsed byNotes
NTFSWindowspermissions, encryption, journaling
ext4Linuxjournaling, good performance, default on many distributions
APFSmacOS and iOSsnapshots and built-in encryption
FAT32 / exFATUSB sticks and cardsworks everywhere; FAT32 cannot hold a file over 4 GB

Journaling means the system records an operation in a log before doing it, so after a power cut it replays the log and repairs the state instead of scanning the whole disk.

Exercise Why is deleting a huge file instant while copying it takes time?
Show solution

Deleting removes the directory entry and marks the blocks free without erasing their content. Copying reads every block and writes it elsewhere. That is also why a deleted file can sometimes be recovered before new data overwrites it.

Summary

  • A file system turns disk blocks into names and folders.
  • The name lives in the directory; the data in the inode and blocks.
  • Journaling protects against power loss.

Core concept

The file system gives data names, structure and permissions on top of a disk that only knows blocks.

Hands-on practice

Try it yourself

Run <code>df -h</code> (Linux/macOS) or open “This PC” (Windows) and record the file system type of each drive.

Test yourself

  1. What happens on a page fault?

    • The kernel loads the missing page from disk and execution continues
    • The program is always deleted
    • The machine powers off
    • Memory is erased
    Answer and explanation

    Correct answer: The kernel loads the missing page from disk and execution continues

  2. With 4096-byte pages, what are the page number and offset of address 0x00005FFF?

    • Page 5, offset 0xFFF
    • Page 0xFFF, offset 5
    • Page 6, offset 0
    • Page 4, offset 0x5FF
    Answer and explanation

    Correct answer: Page 5, offset 0xFFF

    The offset is the low 12 bits (0xFFF) and the page number is the address shifted right by 12, which is 5.

  3. What is wrong with saying virtual memory means extra RAM?

    • Nothing is wrong
    • It is an abstraction plus protection, and swap is far slower than RAM
    • It is a full virtual machine
    • It is memory faster than RAM
    Answer and explanation

    Correct answer: It is an abstraction plus protection, and swap is far slower than RAM

    It gives each process a private address space and adds neither real capacity nor speed.

  4. A machine becomes extremely slow because the kernel constantly moves pages between RAM and disk. What is this called?

    • Ideal paging
    • Thrashing
    • Booting
    • Caching
    Answer and explanation

    Correct answer: Thrashing

    Constant page faults signal memory pressure and are called thrashing.

  5. What happens when a process touches a forbidden address?

    • It gets extra RAM
    • It runs faster
    • A segmentation fault occurs and the kernel terminates the process
    • The whole system restarts
    Answer and explanation

    Correct answer: A segmentation fault occurs and the kernel terminates the process

    Each page has read, write and execute permissions, and violating them ends only the offending process.
