Users, Permissions and OS Security

Learning objectives

  • Read Linux file permissions (rwx).
  • Understand the least privilege principle.
  • Know the difference between authentication and authorisation.

Prerequisites

  • The files (com-11), cybersecurity (com-17) and OS architecture (com-21) lessons.

Who are you, and what may you do?

Authentication answers “who are you?” (password, fingerprint, key). Authorization answers “what are you allowed to do?”. The system checks the second every time you open a file or run a program.

Unix permissions

Every file has an owner, a group and everyone else, and each class has three permissions: read r, write w and execute x.

PartValueMeaning
Ownerrwxsara: read, write, execute
Groupr-xdevs: read and execute only
Others---nothing

Numeric form: r=4, w=2, x=1, so the permissions above equal 750.

Windows and UAC

Windows uses access control lists (ACLs), finer than rwx, and adds UAC: even an administrator runs with ordinary rights until they approve a confirmation prompt.

Common mistakes

  • Setting permissions to 777 to fix “Permission denied”; that opens the file to everyone.
  • Always working as administrator: any malware inherits those rights.
Exercise What are the permissions of a file set to 640? Who can edit it?
Show solution

6 = rw- for the owner, 4 = r-- for the group, 0 = nothing for others. Only the owner can edit it; group members can only read it.

Summary

  • Authentication proves identity; authorisation decides what is allowed.
  • rwx is the basis of Unix permissions, and least privilege is the golden rule.

Core concept

A secure system trusts no program or user more than necessary.

Hands-on practice

Try it yourself

Create a test file and set its permissions to 600, then 644, then 755, and note the <code>ls -l</code> output each time.

Test yourself

  1. Which boot order is correct?

    • Firmware, then bootloader, then kernel
    • Kernel, then firmware, then bootloader
    • Bootloader, then firmware, then kernel
    • Desktop, then kernel
    Answer and explanation

    Correct answer: Firmware, then bootloader, then kernel

  2. After installing Windows after Linux, the Linux option vanished at startup. What is the likely explanation?

    • The disk burned out
    • The Windows installer replaced the bootloader with its own, which does not know Linux
    • The kernel was deleted from RAM
    • Linux expired
    Answer and explanation

    Correct answer: The Windows installer replaced the bootloader with its own, which does not know Linux

    The fix is reinstalling GRUB or adding a Linux entry in the UEFI settings.

  3. What does Secure Boot in UEFI do?

    • Speeds up the internet
    • Verifies the bootloader signature before running it
    • Removes viruses automatically
    • Compresses the disk
    Answer and explanation

    Correct answer: Verifies the bootloader signature before running it

    Old BIOS verifies nothing, while UEFI can block unsigned bootloaders.

  4. Which part loads the kernel into RAM?

    • POST
    • The power supply
    • The bootloader such as GRUB
    • The login screen
    Answer and explanation

    Correct answer: The bootloader such as GRUB

    The firmware finds the boot device and starts the bootloader, which loads the kernel.

  5. Which is the first process started after kernel initialisation on modern Linux?

    • systemd (init)
    • wininit
    • GRUB
    • POST
    Answer and explanation

    Correct answer: systemd (init)

    The first process starts the other services; wininit is the Windows counterpart.
