System Calls and the Shell

Learning objectives

  • Explain what a System Call is and how a program moves from User Mode to Kernel Mode.
  • Trace what happens when a file is read.
  • Understand the role of the shell.

Prerequisites

  • The OS architecture lesson (com-21).

The only door into the kernel

Because applications may not touch hardware, they request every service through a System Call: a structured request to the kernel, such as opening a file, creating a process or sending data over the network. A special CPU instruction moves execution into the kernel in Kernel Mode, and when the request finishes execution returns to the program.

Watching system calls for real

The number 3 is a File Descriptor: a handle the kernel gives to the open file. The number 1 is standard output (the screen).

The shell

The shell is an ordinary User Space program that reads what you type and asks the kernel to run programs. A command line (Bash or PowerShell) is a text shell, and a graphical desktop is a graphical shell. There is nothing magical about it: it is an application like any other.

Exercise Why can a program not run a disk-read instruction directly?
Show solution

Because I/O instructions are reserved for Kernel Mode. If any program could run them it would bypass permission checks and read other users' files. The system makes the kernel the single point of control.

Summary

  • A system call is the structured way to request a kernel service.
  • Switching between modes is enforced by a special CPU instruction.
  • The shell is an ordinary application, not part of the kernel.

Core concept

Everything an application does beyond its own boundaries, from opening a file to opening a connection, goes through a system call.

Hands-on practice

Try it yourself

On Linux or macOS try <code>ls -l</code> then <code>strace -c ls</code> (or <code>dtruss</code>) and compare the number of calls. On Windows, read about Process Monitor.

Test yourself

  1. Where do ordinary applications run?

    • User Space with restricted privileges
    • Kernel Space with full privileges
    • Inside the CPU only
    • Inside the disk
    Answer and explanation

    Correct answer: User Space with restricted privileges

  2. Why does a bug in the browser crash only the browser, while a bug in a device driver can bring down the whole system?

    • The browser runs in Kernel Space
    • The driver runs in User Space with no privileges
    • The browser is isolated in User Space while the driver runs with full privilege in the kernel
    • Both run with the same privileges
    Answer and explanation

    Correct answer: The browser is isolated in User Space while the driver runs with full privilege in the kernel

    A fault in fully privileged space can corrupt memory and hardware, while an application fault only ends that process.

  3. Which kernel keeps only the minimum inside and runs other services as ordinary processes?

    • Monolithic kernel
    • Microkernel
    • No such type exists
    • A browser kernel
    Answer and explanation

    Correct answer: Microkernel

    A microkernel such as MINIX or QNX is more isolated but slightly slower.

  4. Which statement confuses the kernel with the operating system?

    • The kernel is part of the operating system
    • Ubuntu is the Linux kernel plus libraries, tools and a desktop
    • The kernel is the entire operating system and nothing else
    • Strictly, Linux is only a kernel
    Answer and explanation

    Correct answer: The kernel is the entire operating system and nothing else

    The kernel is part of the system, not all of it; libraries and tools belong too.

  5. What happens when an application in User Mode runs a sensitive instruction like changing memory tables?

    • It runs silently
    • The CPU refuses it and raises an exception handled by the OS
    • The computer reboots immediately
    • It is moved to disk
    Answer and explanation

    Correct answer: The CPU refuses it and raises an exception handled by the OS

    The CPU itself enforces the mode split and blocks sensitive instructions outside kernel mode.
