The Browser and the Web

Learning objectives

  • Tell the Internet, the Web and a Browser apart and explain how they relate.
  • Break a URL into its parts and trace what happens from clicking a link to seeing the page.
  • Use the browser developer tools to read requests and status codes yourself.

Prerequisites

  • The lesson “Internet and networks” (com-15); “How a program runs” (com-14) also helps.

Introduction: three things people mix up

Many people say “I opened the internet” when they mean they opened a website. In reality there are three different layers. The Internet is the network of networks: the cables, routers and agreements that move packets between devices. The Web is a service running on top of it, a vast collection of linked documents and applications reached through addresses and the HTTP protocol. A Browser is the program on your device that requests those documents and displays them. Email and online games use the same internet without being part of the web.

Anatomy of a URL

A URL (Uniform Resource Locator) states where a resource is and how to reach it. Take this example and split it up:

  • Scheme: the protocol, here https, meaning HTTP with encryption.
  • Host: the server name shop.example.com, which DNS translates into an IP address.
  • Port: the door number on the server; 443 is the default for HTTPS, so it is usually omitted.
  • Path: which resource we want on that server.
  • Query: parameters sent to the server after the ? sign, separated by &.
  • Fragment: what follows # stays in the browser and is not sent to the server; it points to a spot inside the page.

The first lines are a request, and the lines after the blank one are a response header. HTTP is a simple text protocol of request and response, and by itself the server does not remember who you are between two requests; that is where cookies come in, as we will see.

HTTP methods and status codes

A request states what we want with a Method, and the response answers with a three-digit Status Code showing the outcome. The first digit gives the class.

ItemMeaningExample
GETfetch a resource without changing anythingopening a page
POSTsend data to be processedsubmitting a login form
200successthe page loaded
301moved permanently to another addressfrom http to https
404the server works but cannot find the resourcea broken link
500an error inside the server itselfa bug in the site code

What the browser does with the page

The response is HTML text describing the page structure: headings, paragraphs, images and links. The browser reads it and builds a tree called the DOM. While reading it finds references to other files and requests them: CSS, which sets colours and layout; JavaScript, which adds behaviour and interactivity; and images and fonts. Then it paints the page on screen. This is why a single page often needs dozens of requests.

To save time the browser keeps copies of files in a Cache on your device, so it does not re-download the same logo on every page. Cookies are small pieces of text the browser stores at a site's request and sends back with every later request to it; that is how a site remembers you are signed in or that you picked a language. A cookie is not a program and executes nothing; it is only data.

Hands-on: the Network tab in developer tools

Open any site, press F12 (or Ctrl+Shift+I, and on macOS Cmd+Option+I) and choose the Network tab, then reload the page. You will see a table of every request the browser made.

  • The Status column shows the status code; look for the red ones (4xx and 5xx).
  • The Time column reveals slow requests that delay the page.
  • Click any request to see its request headers, response headers and the cookies sent.

Real-world applications

  • Debugging: seeing 500 in the Network tab tells a developer the fault is on the server, not in the browser.
  • Performance tuning: site teams shrink images and cut request counts to load faster.
  • Search visibility: a permanent 301 redirect preserves the value of an old link when a site moves.
  • Privacy: understanding cookies helps you manage what each site tracks about you.

Common mistakes

  • “The internet and the web are the same”: the web is one service on top of the internet; email, video calls and system updates use the internet without a browser.
  • “The browser is the search engine”: the browser is a program on your device, while a search engine is a site on remote servers that you open through it.
  • “The HTTPS padlock means the site is safe and honest”: the padlock only means the connection to that server is encrypted; the site's intentions are another matter.
  • “Cookies are viruses”: a cookie is text holding a small piece of information and never runs, though some are used for tracking, so managing them is your right.
Exercise Analysis: split https://docs.example.org/guide/install?lang=ar#step-3 into its parts and say which part never reaches the server.
Show solution

The scheme is https, the host is docs.example.org, the path is /guide/install, the query is lang=ar and the fragment is step-3. The part that is not sent to the server is the fragment; the browser uses it locally to scroll to a position in the page.

Exercise Reasoning: you revisit a known site and the page appears faster than the first time. Name two steps in the journey that caching saved.
Show solution

First the DNS step: your system or browser keeps the IP address for a while, so it does not ask again. Second, downloading static files such as CSS and images: if the stored copy is still valid it is not downloaded again, and the server may just answer 304. In some cases an existing connection is reused, which also skips the handshake.

Exercise Hands-on: open the Network tab on a site you visit often and reload. Record the number of requests, the largest file, and any status code other than 200.
Show solution

You will typically see dozens to hundreds of requests for one page. The largest file is usually an image, a JavaScript bundle or a video; sort the Size column in descending order to find it. Codes such as 304 appear for cached files, 301 or 302 for redirects, and you may spot a 404 for a missing file the visitor never notices. If you tick Disable cache and reload, you will see full sizes and longer times, which shows the effect of caching in practice.

Summary

  • The internet is a network, the web is a service over it, and the browser is the program that shows it.
  • A URL has scheme, host, path, query and fragment, and a request passes through DNS, TCP, TLS and then HTTP.
  • The 2xx, 3xx, 4xx and 5xx codes summarise each request, and the Network tab displays them.
  • Cache and cookies make the web faster and keep sessions continuous.

Hands-on practice

Try it yourself

Open DevTools in your browser and look at the HTML and CSS of a simple page.

Test yourself

  1. Which of the following is a Web Browser?

    • Chrome
    • RAM
    • CPU
    • SSD
    Answer and explanation

    Correct answer: Chrome

  2. In the link https://shop.example.com/books?q=linux#reviews, which part is not sent to the server?

    • q=linux
    • books
    • reviews after the # sign
    • shop.example.com
    Answer and explanation

    Correct answer: reviews after the # sign

    The fragment after # stays in the browser and only points to a spot inside the page.

  3. A user opens a page and sees status 404. What does it mean?

    • The server itself crashed because of a bug
    • The server works but cannot find the requested resource
    • The page was moved permanently to another address
    • The request succeeded and the page loaded
    Answer and explanation

    Correct answer: The server works but cannot find the requested resource

    4xx codes mean a problem with the request, and 404 means the resource is missing, like a broken link.

  4. Which order is correct for what happens after typing an address and pressing Enter?

    • TLS, then DNS, then HTTP, then TCP
    • HTTP, then DNS, then TCP, then TLS
    • TCP, then HTTP, then DNS, then TLS
    • DNS, then TCP, then TLS, then the HTTP request
    Answer and explanation

    Correct answer: DNS, then TCP, then TLS, then the HTTP request

    The name is resolved to an IP first, then TCP connects, TLS secures it, and only then is the HTTP request sent.

  5. In the Network tab, logo.svg shows 304 and is served from cache. What does that mean?

    • Your cached copy is still valid so the content was not sent again
    • The file does not exist on the server
    • An error occurred inside the server
    • The file was moved permanently to a new address
    Answer and explanation

    Correct answer: Your cached copy is still valid so the content was not sent again

    Code 304 means the cached copy is still good, which saves time and bandwidth.
