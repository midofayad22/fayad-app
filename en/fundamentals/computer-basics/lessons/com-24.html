Memory Management and Virtual Memory

Learning objectives

  • Explain why programs do not use physical memory addresses directly.
  • Understand paging and the page table.
  • Know what a page fault and swap are.

Prerequisites

  • The RAM lesson (com-05) and the processes lesson (com-23).

Why virtual memory?

If every process used real memory addresses they would overlap and one would overwrite another's data. The solution is virtual memory: each program sees a private address space starting at zero, and a CPU unit called the MMU translates it into physical addresses using tables set by the kernel.

Paging

Memory is divided into fixed-size blocks, usually 4 KB: pages in virtual addresses and frames in RAM. A program's pages need not be contiguous in RAM, which avoids large-region fragmentation.

Page fault and swap

If the requested page is not in RAM a page fault occurs: the kernel loads it from disk (from the file or from the swap area) and the process continues. When RAM fills up the kernel evicts pages that have not been used recently. If this happens constantly the machine becomes extremely slow, which is called thrashing.

Common mistakes

  • Thinking virtual memory means extra RAM; it is an abstraction plus protection, and swap is orders of magnitude slower than RAM.
  • Confusing virtual memory with a virtual machine.
Exercise With a 4096-byte page, what are the page number and offset of address 0x00005FFF?
Show solution

Page number = 0x5FFF >> 12 = 5, offset = 0x5FFF & 0xFFF = 0xFFF (the last byte of the page).

Summary

  • Each process sees a private address space which the MMU translates.
  • Pages give isolation and flexible use of RAM.
  • Occasional page faults are normal; many mean memory pressure.

Core concept

Virtual memory lets each program believe it owns the machine, and protects it from the others.

Hands-on practice

Try it yourself

On Linux run <code>free -h</code>; on Windows open Task Manager > Performance > Memory. Record used and available memory and the swap/page file size.

Test yourself

  1. What is a context switch?

    • Saving one process state and loading another onto the CPU
    • Changing the system language
    • Swapping the hard disk
    • Restarting the machine
    Answer and explanation

    Correct answer: Saving one process state and loading another onto the CPU

  2. Three processes arrive at 0 needing 8, 4 and 2 ms in that order under FCFS. What is the average wait?

    • 2.67 ms
    • 4.67 ms
    • 6.67 ms
    • 14 ms
    Answer and explanation

    Correct answer: 6.67 ms

    Waits are 0, 8 and 12; the sum 20 divided by 3 is 6.67.

  3. What is the drawback of simple priority scheduling?

    • It gives no process any time
    • Low-priority processes may starve, fixed with aging
    • It always needs a single CPU
    • It removes context switching
    Answer and explanation

    Correct answer: Low-priority processes may starve, fixed with aging

    High priorities always go first, so aging raises the priority of long-waiting processes.

  4. In Round Robin, what happens when the quantum ends and the process is not finished?

    • The process is terminated at once
    • It goes to the back of the queue and the next process gets its turn
    • It keeps the CPU forever
    • It is removed from memory
    Answer and explanation

    Correct answer: It goes to the back of the queue and the next process gets its turn

    Taking turns gives everyone a fair share, but a tiny quantum causes many switches.

  5. What does a context switch involve?

    • Saving the current process state and loading the next one's
    • Rebooting the computer
    • Copying the disk to RAM
    • Changing the system language
    Answer and explanation

    Correct answer: Saving the current process state and loading the next one's

    Switching enables sharing but is not free; it costs time.
