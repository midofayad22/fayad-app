How Does a Computer Work?

Learning objectives

  • Trace the journey of data between input, memory, the processor and output.
  • Explain the Fetch-Decode-Execute cycle and what clock cycles mean.
  • Describe what happens from pressing the power button to seeing the desktop.

Prerequisites

  • The lesson “What is a computer?” (com-01).

Introduction: between the click and the result

When you click your browser icon, about a second passes before the window appears. In that second billions of tiny steps happen: reading from disk, moving data into memory, executing instructions on the processor, and drawing on the screen. This lesson gives you the big picture before later lessons examine each component on its own.

The core components and their roles

Four parts work together, linked by what is called a Bus: electrical pathways that carry data, addresses and control signals. The parts are the CPU, which executes instructions; RAM, which holds what we are working on right now; Storage, which keeps everything permanently; and the input and output devices.

The Fetch-Decode-Execute cycle

The processor does not understand whole programs; it carries out very simple instructions one after another, such as “add these two numbers” or “copy a value from memory”. Each instruction goes through three steps that repeat without stopping:

  1. Fetch: the CPU fetches the next instruction from memory; a special counter called the Program Counter tracks where it is.
  2. Decode: the control unit works out what the instruction means and what is required.
  3. Execute: the ALU (arithmetic logic unit) performs the operation, and the result is stored in a register or in memory.

This is a simplified assembly language that shows the idea: four instructions, each passing through the three steps, and at the end memory holds the value 8. A high-level statement such as total = 5 + 3 is translated into a sequence like this.

The clock and speed

The processor works to a steady rhythm set by an internal clock, and each beat is a Clock Cycle. A 3.5 GHz processor ticks about 3.5 billion times per second, so one cycle lasts roughly 0.29 nanoseconds. Even so, instructions completed per second is not exactly the frequency: some instructions need several cycles and others run alongside each other. We return to this in the CPU lesson.

From the power button to the desktop

When you open a program afterwards, the same pattern repeats on a smaller scale: the program is copied from disk into memory, then the processor begins fetching its instructions. That is why the first launch is sometimes slower than the second: part of the files stay cached in memory.

Real-world applications

  • Diagnosing slowness: knowing that the CPU, memory and disk share the work tells you that a machine that slows down with many programs open usually lacks memory rather than CPU power.
  • Choosing upgrades: replacing a spinning hard disk with an SSD speeds up boot more than changing the CPU in many older computers.
  • Dual boot and repair: understanding firmware and the bootloader explains how Linux is installed beside Windows and how to repair a machine that will not start.

Common mistakes

  • “The CPU stores my files”: the CPU stores nothing permanently; files live on disk and the CPU only processes what reaches it temporarily.
  • “The CPU reads the program straight from disk”: the program must be copied into memory first, because the disk is far too slow for the processor.
  • “The machine is slow, so the CPU is weak”: slowness can come from memory, disk, network or software; a system is only as fast as its slowest link.
Exercise Calculation: a processor runs at 4 GHz. How many nanoseconds does one cycle take, and how many cycles occur in one millisecond?
Show solution

4 GHz means 4 billion cycles per second, so one cycle = 1 ÷ 4,000,000,000 = 0.25 nanoseconds. In one millisecond (a thousandth of a second) there are 4,000,000,000 ÷ 1000 = 4,000,000 cycles.

Exercise Reasoning: why is a program not loaded from disk straight into the processor, skipping memory?
Show solution

A processor executes billions of instructions per second, while a good SSD needs tens of microseconds to serve one request and a spinning disk several milliseconds. If the CPU waited on the disk for each instruction it would sit idle most of the time. Memory is hundreds of times faster, so it acts as a middleman that feeds the CPU what it needs.

Exercise Hands-on: open Task Manager or Activity Monitor and watch CPU, memory and disk usage before launching your browser and after opening several tabs. What do you expect to see?
Show solution

On launch, disk usage rises briefly as files are read; memory then climbs noticeably with each tab, while the CPU spikes momentarily as pages load and then settles. If memory gets close to full you will see the disk working continuously, a sign that the system is using it as a temporary substitute for memory.

Summary

  • Data moves from input and storage into memory and then the CPU, and the result returns to output or storage.
  • The CPU runs its instructions through the Fetch-Decode-Execute cycle at the pace of the clock.
  • Booting is a chain: firmware, then the bootloader, then the operating system.
  • System performance is set by the balance of its parts, not one part.

Core concept

A computer is an interconnected system; the speed and performance of the system depend on several components working together, not just one.

Hands-on practice

Try it yourself

Open a program on your device and observe what happens: clicking the icon, the program loading, and then its interface appearing.

Test yourself

  1. Which component is primarily responsible for executing instructions?

    • The monitor
    • The keyboard
    • CPU
    • The speakers
    Answer and explanation

    Correct answer: CPU

  2. What is the order of the steps every instruction goes through in the processor?

    • Execute, then Fetch, then Decode
    • Decode, then Execute, then Fetch
    • Fetch, then Execute, then Decode
    • Fetch, then Decode, then Execute
    Answer and explanation

    Correct answer: Fetch, then Decode, then Execute

    The CPU fetches the instruction, decodes it, then executes it, and the cycle repeats without stopping.

  3. What does the Program Counter do?

    • It counts the open programs
    • It tracks where the next instruction to fetch is in memory
    • It measures the clock speed
    • It stores permanent files
    Answer and explanation

    Correct answer: It tracks where the next instruction to fetch is in memory

    The counter points to the address of the next instruction so it can be fetched in the Fetch step.

  4. A processor runs at 3.5 GHz. Roughly what does that mean?

    • It ticks about 3.5 billion clock cycles per second
    • It runs 3.5 million instructions per second
    • It needs 3.5 seconds to start a program
    • It has 3.5 GB of memory
    Answer and explanation

    Correct answer: It ticks about 3.5 billion clock cycles per second

    GHz measures clock cycles, each about 0.29 nanoseconds, which is not necessarily the number of instructions.

  5. Which sequence describes the boot process after pressing the power button?

    • Operating system, POST, firmware, bootloader
    • Firmware, POST, bootloader, operating system
    • Bootloader, operating system, POST, firmware
    • Desktop, operating system, firmware
    Answer and explanation

    Correct answer: Firmware, POST, bootloader, operating system

    The firmware checks the hardware (POST), finds the bootloader, which loads the OS, and then the desktop appears.
