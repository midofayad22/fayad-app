CPU Scheduling

Learning objectives

  • Explain why scheduling is needed and how multitasking works.
  • Compare FCFS, Round Robin and priority schemes.
  • Compute the average waiting time for a simple example.

Prerequisites

  • The processes and threads lesson (com-23).

The problem

Your machine has dozens of processes but only a few cores. The scheduler is the kernel part that picks which process gets the CPU next. The system switches between processes thousands of times per second so they appear to run together; a switch is called a context switch: save the current process state and load the next one.

Common algorithms

AlgorithmIdeaDrawback
FCFSFirst come, first servedOne long job delays everyone
SJFShortest job firstNeeds time estimates; can starve long jobs
Round RobinEach process gets a time slice (quantum), then goes to the back of the queueMany switches if the slice is tiny
PriorityHighest priority firstStarvation, fixed with aging

Exercise In Round Robin with a 2 ms quantum, three processes need 5, 3 and 1 ms. What is the execution order?
Show solution

P1 (2), P2 (2), P3 (1, done), P1 (2), P2 (1, done), P1 (1, done).

Summary

  • The scheduler shares CPU time, and switching has a cost.
  • No algorithm is perfect; each trades fairness, throughput and responsiveness.

Next step: What about memory? The kernel manages that too.

Core concept

Scheduling creates the illusion of parallelism: the CPU hops between processes faster than you can notice.

Hands-on practice

Try it yourself

Compute the average FCFS waiting time yourself for three processes of 6, 3 and 1 ms, then recompute using SJF order.

Test yourself

  1. What do the threads of one process share?

    • Memory and open files
    • The stack and registers
    • A separate PID each
    • Nothing
    Answer and explanation

    Correct answer: Memory and open files

  2. You launched the same editor twice. How many programs and processes do you have?

    • Two programs and one process
    • One program and two processes
    • One program and one process
    • Two programs and two processes
    Answer and explanation

    Correct answer: One program and two processes

    The program is one file on disk, and each run is a separate process with its own PID.

  3. A process is waiting for a disk read to finish. Which state is it in?

    • Running
    • Ready
    • Waiting
    • Terminated
    Answer and explanation

    Correct answer: Waiting

    Waiting means waiting for an event such as a finished read or a key press.

  4. Which of these does the kernel store in the PCB?

    • The user's password
    • The PID, process state, register values and open files
    • The screen contents
    • The browsing history
    Answer and explanation

    Correct answer: The PID, process state, register values and open files

    The PCB holds what is needed to pause and resume a process.

  5. What is the problem when two threads change the same shared variable without a lock?

    • None, since each thread has separate memory
    • A race condition where the result depends on thread timing
    • The threads turn into processes
    • The CPU stops permanently
    Answer and explanation

    Correct answer: A race condition where the result depends on thread timing

    Threads share the process memory, so uncoordinated access gives unpredictable results.
