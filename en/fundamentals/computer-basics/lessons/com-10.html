Operating Systems

Learning objectives

  • Define an Operating System and list its core duties.
  • Distinguish the Kernel, applications and interface, and grasp multitasking.
  • Recognise Windows, macOS, Linux, Android and iOS and choose what fits a need.

Prerequisites

  • The hardware and software (com-03), RAM (com-05) and I/O devices (com-09) lessons.

Introduction: who runs the show?

Imagine ten programs all wanting the processor, memory, screen and disk at the same time. Left alone they would collide and corrupt each other's data. The Operating System is the foundational program that manages the hardware and lets other programs use it safely and in order. It is the go-between for you and the machine, and for programs and the machine.

This lesson is a general introduction. The advanced section of the path (lessons 21–30) studies OS internals in detail, so we will not repeat that here.

What does an operating system do?

  • Process management: decides which program uses the CPU and for how long; each running program is called a Process.
  • Memory management: gives each program a region of RAM and stops it from touching anyone else's.
  • File management: organises storage into files and folders using the file system.
  • Device management: deals with the keyboard, screen and network through drivers.
  • Security and users: accounts, permissions and security updates.
  • Interface: a desktop, touchscreen or command line for interacting with it.

The layers: hardware, kernel and applications

The Kernel is the core of the system and runs with high privilege, while applications run with limited privilege. When an application wants to read a file, it does not read the disk itself; it asks the kernel through what is called a System Call. This separation protects the system: a crashing application does not bring down the whole machine. The advanced section's architecture lesson covers this in depth.

Multitasking: the illusion of parallelism

While you listen to music, type and download a file, it seems everything happens together. In truth, the kernel carves time into very short Time Slices measured in milliseconds and switches the processor between programs faster than you can perceive. On multi-core processors several programs really do run at the same instant, each on its own core.

In this example each program gets another turn every 40 ms and 25% of the time, which is below what a user notices, so responses seem continuous.

Note that Linux is really the name of the kernel started by Linus Torvalds in 1991; what people install is a Distribution that bundles the kernel with tools and an interface. There is no single “best” system: the choice depends on the software you need, your hardware, your experience and your budget.

Real-world applications

  • Updates: they patch OS vulnerabilities and add features; postponing them leaves a machine exposed to attacks.
  • Virtual machines: running more than one OS on a single device to test software or try Linux safely.
  • Choosing a device: before buying, check that the programs you rely on run on that device's OS.

Common mistakes

  • “The OS is the interface I see”: the interface is one part; most of the OS's work happens in the kernel behind the scenes.
  • “Linux is one system”: there are dozens of distributions differing in interface, tools and support period.
  • “Multitasking means everything runs literally at once”: on one core the system alternates between programs extremely quickly.
  • “Android and iOS are the same since both are for phones”: they have different origins, different companies and different approaches.
Exercise Calculation: a single-core system with a 20 ms time slice runs 5 processes in turn. After how many milliseconds does the first process get another turn, and what share of time does each receive?
Show solution

A full round = 5 × 20 = 100 ms, so the first process runs again after 100 ms. Each process gets 1 ÷ 5 = 20% (ignoring the switching cost itself, which takes a small slice). Since 100 ms is near the threshold of human perception, a user might begin to notice lag, so systems use shorter slices and priorities.

Exercise Reasoning: why does the OS not let an application read memory used by another application? What could happen if it did?
Show solution

Isolation delivers stability and security together. If a program could write into another's memory, it could corrupt its data or crash it with a simple bug, and a malicious program could read passwords from the browser. So the kernel gives each process its own address space, and any attempt to trespass stops only the offending program with an error while the rest keep running.

Exercise Hands-on: find the operating system and version on your device, then open the list of running processes and name three of them with their roles.
Show solution

On Windows press the Windows key with R and type winver. On macOS choose About This Mac. On Linux open a terminal and type uname -a. Then open Task Manager or Activity Monitor: you will typically find a browser process (an application), a process such as Explorer or Finder (the interface and file management), and a system service or antivirus process (a background service). Notice how many processes run even with no applications open; that shows how much the system manages behind the scenes.

Summary

  • The operating system manages the processor, memory, files, devices and security, and provides the interface.
  • The kernel runs with top privilege, and applications request services from it through system calls.
  • Multitasking is rapid alternation between programs plus true parallel running on multiple cores.
  • No system is best in absolute terms; choose by need.

Hands-on practice

Try it yourself

Identify the operating system you are using right now, then look up its version.

Test yourself

  1. What is the main function of an operating system?

    • Managing the device's resources
    • Enlarging the screen
    • Replacing the CPU
    • Creating the internet
    Answer and explanation

    Correct answer: Managing the device's resources

  2. What is a system call?

    • An error that halts the machine
    • A phone call over the network
    • A tool to speed up the processor
    • A request from an application to the kernel to do something such as read a file
    Answer and explanation

    Correct answer: A request from an application to the kernel to do something such as read a file

    An application does not read the disk itself but asks the kernel, which protects the system.

  3. A single core, a 10 ms time slice and 4 processes. How long does each process wait between turns?

    • 10 ms
    • 30 ms
    • 40 ms
    • 100 ms
    Answer and explanation

    Correct answer: 30 ms

    The other three run for 30 ms before your turn returns, so each gets 25% of the time.

  4. How is Android related to Linux?

    • They are unrelated
    • Linux is built on top of Android
    • Android is built on the Linux kernel
    • Android is a copy of Windows
    Answer and explanation

    Correct answer: Android is built on the Linux kernel

    Linux is the kernel's name, and Android is a system built on it and the most widely used phone OS.

  5. Why does the whole machine not go down when a single application crashes?

    • Because applications run with limited privilege and only the kernel controls the hardware
    • Because applications do not use the CPU
    • Because the system ignores errors
    • Because crashes are impossible
    Answer and explanation

    Correct answer: Because applications run with limited privilege and only the kernel controls the hardware

    Privilege separation between kernel and applications isolates an application's faults from the rest.
