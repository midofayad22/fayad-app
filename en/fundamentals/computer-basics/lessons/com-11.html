Files and Folders

Learning objectives

  • Read an absolute and a relative Path and locate any file in the folder tree.
  • Understand the role of an Extension and the rules for naming files.
  • Tell copying, moving and deleting apart, and perform them in the interface and on the command line.

Prerequisites

  • The storage (com-06) and operating-system (com-10) lessons.

Introduction: how does the computer find your file among millions?

We saw that a drive keeps data permanently, but at heart it is just a vast stretch of bytes. What makes it organised is the File System: a layer managed by the operating system that records, for every piece of data, a name, a size, dates and a location on the drive. The basic unit we deal with is the File: one named collection of data, whether a document, a picture or a program.

Because files number in the tens of thousands, we group them in a Folder (called a Directory among developers). A folder is a container that holds files and other folders, and this nesting builds a clear hierarchy you can follow step by step.

The folder tree and paths

The tree has a single root Root on Linux and macOS, written /. On Windows each drive or partition has its own root with a letter such as C: and D:. A Path is the address describing the way from some starting point to the file, with its parts separated by a forward slash / on Linux and macOS and a backslash on Windows.

KindDefinitionExample (Linux)
Absolute Pathstarts at the root and means the same wherever you stand/home/sara/Documents/report.docx
Relative Pathstarts at the current folder, so its meaning changes with where you areDocuments/report.docx
The symbol .the current folder./report.docx
The symbol ..the parent folder (one level up)../Pictures/trip.jpg

If you are inside /home/sara/Documents, the path ../Pictures/trip.jpg means: go up to /home/sara, enter Pictures and pick the image. The folder you are working in right now is called the Working Directory.

Names and extensions

A file name usually has two parts separated by a dot: the name and the Extension, as in report.docx. The extension does not change what is inside the file; it is a hint the system uses to choose which program opens it. Renaming photo.png to photo.txt does not turn the picture into text; the system will try a text editor and show meaningless symbols.

  • Characters forbidden on Windows: < > : " / | ? *, and a name may not end in a dot or a space.
  • Length: a single name is usually limited to 255 characters, and some versions limit the full path as well.
  • Letter case: on Linux Report.txt and report.txt are different files, whereas Windows and macOS normally treat them as one name.
  • Hidden files: on Linux and macOS a hidden file's name begins with a dot, such as .config.

Copy, move and delete

  • Copy: creates an identical file elsewhere and leaves the original, so the space used doubles.
  • Move: changes where the file lives so it no longer sits in the old place. Within the same drive the system only edits its index entry, so a move is instant however large the file; between two drives the file is copied and the original then deleted.
  • Delete: in the interface files normally go to the Recycle Bin and can be restored. The rm command on the command line deletes directly, with no bin.

Real-world applications

  • Organising work: a layout such as project/source/images lets a team find any file without asking anyone.
  • Websites: the address /images/logo.png in a link is a real path to a file on the server.
  • Programming: code uses relative paths to read configuration files, so a project moves between machines unchanged.

Common mistakes

  • “Changing the extension converts the file”: the content is unchanged; to really turn a .png into a .jpg you need a tool that re-encodes the data.
  • “A folder and a file are the same thing”: a folder holds organising information only, not document content.
  • “Moving is always copy then delete”: within the same drive it is just an index edit and no data moves at all.
  • “Everything I delete comes back from the bin”: the bin does not cover files removed with rm, often not those on external drives, and nothing after it is emptied.
Exercise Reasoning: you are in /home/sara/Documents. Write the relative path to /home/sara/Pictures/trip.jpg, then the absolute one.
Show solution

To reach the picture we go up one level to /home/sara with .. and then enter Pictures, so the relative path is ../Pictures/trip.jpg. The absolute path starts at the root and never changes: /home/sara/Pictures/trip.jpg. If we stood in a different folder the relative path would change but the absolute one would not.

Exercise Calculation: you copy 40 files of 25 MB each from one drive to another, and then consider moving instead of copying. How much space does the target drive use, and how much is used across both drives afterwards?
Show solution

Total size = 40 × 25 = 1,000 MB, about 1 GB. With a copy the target drive uses 1,000 MB and the original stays on the first drive, so the total across both is 2,000 MB. With a move between two drives the target also uses 1,000 MB but the original is deleted once the copy succeeds, leaving a total of 1,000 MB. If the move happens inside a single drive no extra space is needed and it finishes in moments.

Exercise Hands-on: create a folder layout for a study project with commands, copy a file into it, then check the result.
Show solution

Open the terminal and run: mkdir -p study/notes study/files to create both folders at once, then echo "first note" > study/notes/day1.txt to create a file, then cp study/notes/day1.txt study/files/day1-copy.txt to copy it. Finally ls -R study prints the whole tree; expect day1.txt under notes and day1-copy.txt under files. Try mv to relocate one of them and watch the output change. On Windows use File Explorer with right-click to get the same result.

Summary

  • A file is named data and a folder is a container that organises files into a tree with a single root.
  • An absolute path starts at the root; a relative one starts at the current folder and uses . and ...
  • The extension is a hint about file type, not a conversion, and good names are descriptive and clean.
  • Copy duplicates data, move relocates it, and delete may not be recoverable.
