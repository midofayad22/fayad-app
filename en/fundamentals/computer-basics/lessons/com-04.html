The Processor (CPU)

Learning objectives

  • Explain the internal structure of the CPU: the ALU, the Control Unit and Registers.
  • Understand what a Core, a Thread, clock speed and Cache mean.
  • Compare two processors properly instead of relying on clock speed alone.

Prerequisites

  • The lessons “How a computer works” and “Hardware and Software”.

Introduction: the instruction factory

The CPU (central processing unit) is a silicon chip about the size of a postage stamp, yet it holds billions of transistors, tiny electrical switches that open and close to represent 0 and 1. Its core job is the Fetch-Decode-Execute cycle we saw earlier, but what sets one processor apart from another is how it performs that cycle and how many at once.

Internal structure

Cache is arranged in levels: L1 is smallest and fastest (tens of kilobytes per core), then L2, then L3 which is shared between cores and can reach tens of megabytes. When the CPU finds what it needs in cache this is a Cache Hit; otherwise it must go to RAM, which is several times slower.

Cores and threads

A Core is a complete miniature processor inside the chip that can run an instruction stream on its own. A four-core CPU can genuinely work on four tasks at the same moment. Some processors support SMT (such as Intel's Hyper-Threading), which lets each core present itself as two logical cores and so exposes more “threads”; a 4-core / 8-thread chip is a common example.

Extra cores help when the work can be split: video editing, or running several programs together. A program that follows a single path cannot use more than one core.

Clock speed is not everything

Clock speed (GHz) is the number of cycles per second, but what matters is instructions completed per second, roughly clock × IPC, where IPC is the average number of instructions executed per cycle. A newer processor at a lower clock can beat an older one at a higher clock because its IPC is larger.

There is also Boost Clock: the processor raises its frequency temporarily when heat and power allow, then lowers it when it gets hot, which is called thermal throttling.

Architecture: x86 and ARM

Each processor family has its own instruction set, the ISA. Desktop and laptop processors are generally from the x86-64 family (Intel and AMD), while phones and Apple Silicon machines use the ARM architecture, known for energy efficiency. A program compiled for one architecture does not run directly on another without translation or emulation.

Real-world applications

  • Buying a machine: for gaming, per-core performance matters along with a good graphics card; for video editing and compiling code, more cores help.
  • Phones: many phones combine powerful cores with energy-saving ones and switch between them by workload to extend battery life.
  • Servers: server processors can have dozens of cores to handle many requests at once.

Common mistakes

  • “More GHz is always faster”: performance depends on IPC, core count, cache and architecture, not clock speed alone.
  • “Double the cores means double the speed”: that holds only for programs that split their work across cores; others use a single core.
  • “Threads are as good as real cores”: a two-thread core typically gives a gain of roughly 20 to 30 percent, not a full doubling.
  • “The CPU is where the machine keeps its memory”: cache is tiny; the real storage is in RAM and on disk.
Exercise Calculation: processor A runs at 3.0 GHz with IPC = 3, and processor B at 4.0 GHz with IPC = 2 (one core each). Which is faster?
Show solution

A: 3.0 × 3 = 9 billion instructions per second. B: 4.0 × 2 = 8 billion. So A is about 12.5 percent faster despite the lower clock, because IPC makes up for it.

Exercise Reasoning: a program spends half its time on work that can be spread across cores and half on strictly sequential work. Does it get twice as fast with eight cores?
Show solution

No. The sequential part stays as it is. With eight cores the parallel half shrinks to 1/8 of half the time, i.e. 0.0625, plus the sequential 0.5, for a total of 0.5625 of the original time, a speed-up of only about 1.78 times. This is the idea behind Amdahl's law and explains why extra cores do not scale linearly.

Exercise Hands-on: open Task Manager (Windows), then the Performance tab, then CPU, or run lscpu. Write down the number of cores, logical processors and the clock speed, and check how they relate.
Show solution

You may see, for example, “Cores: 6, Logical processors: 12”. If the second number is double the first, the machine supports SMT. The displayed clock can change while you watch, moving between base and boost. If you run a heavy program you can see which cores climb in usage; if only one does, the program is single-threaded.

Summary

  • The CPU combines a control unit, an ALU, registers and cache, and runs instructions through the familiar cycle.
  • Cores enable parallel work, but the gain depends on how well a program can be split.
  • Compare processors by clock, IPC, cores and cache together, not clock alone.

Core concept

Hands-on practice

Try it yourself

Open Task Manager in Windows and look for information about your processor, its number of Cores, and its speed.

Test yourself

  1. What does CPU stand for?

    • Central Processing Unit
    • Computer Program Utility
    • Central Power Unit
    • Computer Processing User
    Answer and explanation

    Correct answer: Central Processing Unit

  2. A CPU has 4 cores and each core supports 2 threads (SMT). How many logical processors will the system show?

    • 4
    • 6
    • 8
    • 16
    Answer and explanation

    Correct answer: 8

    Logical processors = cores x threads per core = 4 x 2 = 8.

  3. An older CPU runs at 4.0 GHz with IPC 2, a newer one at 3.2 GHz with IPC 4. Which is faster by the lesson's rule?

    • The older one, because its clock is higher
    • The newer one (12.8 vs 8 billion instructions/s)
    • They are equal
    • They can never be compared
    Answer and explanation

    Correct answer: The newer one (12.8 vs 8 billion instructions/s)

    Throughput is roughly clock x IPC, so 3.2 x 4 = 12.8 beats 4.0 x 2 = 8.

  4. What does a Cache Hit mean?

    • The processor overheats
    • The program crashes
    • The CPU found what it needed in cache without going to RAM
    • Data is written to disk
    Answer and explanation

    Correct answer: The CPU found what it needed in cache without going to RAM

    Finding data in cache is much faster than going to the comparatively slow RAM.

  5. Does a program compiled for an x86 processor run directly on an ARM processor?

    • Yes, always
    • Yes, but at exactly half speed
    • Only if the clock speed is higher
    • No, it needs translation or emulation because the instruction set differs
    Answer and explanation

    Correct answer: No, it needs translation or emulation because the instruction set differs

    Each processor family has its own instruction set, so a program compiled for one does not run directly on another.
