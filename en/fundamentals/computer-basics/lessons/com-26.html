Drivers, Device Management and Interrupts

Learning objectives

  • Explain the role of a device driver.
  • Distinguish polling from interrupts.
  • Understand DMA and why it saves CPU time.

Prerequisites

  • The input/output devices lesson (com-09) and the OS architecture lesson (com-21).

The variety problem

There are thousands of different devices, each with its own way of being controlled. Having every application contain code for every device would be impossible. The solution: a driver, a program that translates between a uniform interface the OS knows and the language of specific hardware. Your application says “print” and the driver knows how to talk to this exact printer.

Polling or interrupt?

How does the CPU know a keyboard or network card needs attention? Two ways:

  • Polling: the CPU keeps asking the device “anything for me?”. Simple but wasteful.
  • Interrupt: the device sends a signal; the CPU pauses, runs an interrupt handler and then resumes. Far more efficient.

To move large amounts of data (disk, network) systems use DMA (Direct Memory Access): a unit copies data between the device and RAM without the CPU moving it byte by byte, then raises a single interrupt when done.

Common mistakes

  • Updating a driver without noting the previous version: keep a restore point or the old installer.
  • Assuming every device problem is a hardware fault; many are outdated or incompatible drivers.
Exercise Why do interrupts beat polling when the device is slow (like a keyboard)?
Show solution

A keyboard may sit idle for seconds. With polling the CPU wastes millions of cycles asking, while with an interrupt it does other work and is notified only on a key press.

Summary

  • A driver translates between the system and a device.
  • Interrupts save CPU time compared with polling.
  • DMA moves large blocks without occupying the CPU.

Next step: What happens from the moment you press the power button? The boot process.

Core concept

The driver is the translator between OS and hardware, and the interrupt is how hardware asks for attention without wasting the CPU.

Hands-on practice

Try it yourself

Open Device Manager (Windows) or run <code>lspci</code> / <code>system_profiler SPHardwareDataType</code>, and record three devices and the driver controlling each.

Test yourself

  1. Where is a file name stored in Unix systems?

    • In the directory that maps it to an inode number
    • Inside the file content
    • In the CPU
    • On the screen
    Answer and explanation

    Correct answer: In the directory that maps it to an inode number

  2. Why is deleting a huge file instant while copying it takes time?

    • Deleting erases every byte quickly
    • Deleting removes the directory entry and frees blocks without erasing content, while copying reads and writes every block
    • Copying deletes the original first
    • There is no difference
    Answer and explanation

    Correct answer: Deleting removes the directory entry and frees blocks without erasing content, while copying reads and writes every block

    That is why a deleted file can sometimes be recovered before new data overwrites it.

  3. What is the benefit of journaling?

    • It compresses files
    • It logs an operation before doing it so the system can repair itself after a power cut
    • It encrypts the disk
    • It enlarges the disk
    Answer and explanation

    Correct answer: It logs an operation before doing it so the system can repair itself after a power cut

    The system replays the log instead of scanning the whole disk.

  4. Why does copying a 6 GB file to a FAT32 flash drive fail?

    • FAT32 works only on macOS
    • FAT32 cannot hold a file over 4 GB
    • Flash drives do not support files
    • The file has no name
    Answer and explanation

    Correct answer: FAT32 cannot hold a file over 4 GB

    The size limit is a known FAT32 restriction; exFAT or NTFS solves it.

  5. Why should you safely eject a flash drive?

    • Because the system renames it
    • Because ejecting increases capacity
    • Because writes may be delayed in the cache and the file can be corrupted if pulled early
    • Because the drive would explode
    Answer and explanation

    Correct answer: Because writes may be delayed in the cache and the file can be corrupted if pulled early

    The kernel writes to the page cache first and flushes later, and ejecting finishes that.
