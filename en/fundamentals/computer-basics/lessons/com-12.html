Binary and Data

Learning objectives

  • Explain why computers rely on Binary and convert numbers between decimal, binary and hexadecimal.
  • Describe how text is represented with ASCII and Unicode and how UTF-8 encodes characters.
  • Interpret colours in the RGB model and count the possible colours.

Prerequisites

  • The files and folders lesson (com-11) and knowing that memory and storage hold data.

Introduction: everything is numbers

The picture you see, the song you hear and this very sentence are all stored in a computer as numbers, without exception. The working idea is Encoding: an agreement that a given number stands for a letter, a colour or a sound level. When both sides know the agreement, they can rebuild the meaning from the numbers.

But why binary numbers in particular? Because electronic circuits tell two states apart easily and reliably: low voltage or high voltage, current flowing or not. Telling ten delicate electrical levels apart is far more error-prone because of noise and heat. Two states are all we need to build the binary system.

Binary versus decimal

Our Decimal system has ten symbols (0 to 9) and the value of each place is a power of 10: ones, tens, hundreds. Binary has just two symbols (0 and 1) and each place is a power of 2. Each binary digit is called a Bit, short for Binary Digit.

Binary to decimal

Add the values of the places that hold a 1. For 101101 the places are 32, 8, 4 and 1, so the result is 32 + 8 + 4 + 1 = 45. In the table above, 156 equals 128 + 16 + 8 + 4 = 156, which is 10011100.

Hexadecimal

Reading long strings of zeros and ones is tiring, so programmers use Hexadecimal, which has 16 symbols: 0–9 then A–F, where A=10 and F=15. The beauty is that each hex symbol corresponds to exactly four binary digits, so we split the binary into groups of four and convert each group.

For 10011100: the group 1001 is 9 and the group 1100 is 12, which is C, so the hex form is 9C. By direct calculation 9 × 16 + 12 = 156. The largest value in one byte is FF, that is 15 × 16 + 15 = 255. In code, hex numbers usually carry the prefix 0x, as in 0x9C.

Text as numbers: ASCII, Unicode and UTF-8

The oldest widespread agreement is ASCII, which gave 128 symbols numbers from 0 to 127: the letter A is 65, a is 97 and the digit character 0 is 48. So the word Hi is stored as the two numbers 72 and 105, that is 01001000 01101001. Note that the character 0 is not the number zero: the first is a symbol with code 48, the second is a value.

ASCII is not enough for Arabic, Chinese or emoji, so Unicode appeared: a standard that gives every character in every language a unique number called a Code Point, written like U+0639 for the Arabic letter ain. But Unicode fixes only the numbers; how they are stored as bytes is decided by an encoding, the best known being UTF-8.

UTF-8 uses one to four bytes per character: ASCII letters take one byte so it stays compatible with the old standard, é takes two (C3 A9), the Arabic letter ain takes two (D8 B9), the symbol € takes three (E2 82 AC), and emoji usually take four. That is why the number of bytes differs from the number of characters in Arabic text.

Colours as numbers: the RGB model

A dot on a screen is made of red, green and blue light at varying strengths, so the RGB model describes each colour with three numbers, each from 0 to 255, that is one byte: the strength of red, green and blue. Orange (255, 128, 0) is full red, half green and no blue, written in hex as #FF8000 because 255 is FF and 128 is 80.

Three bytes means 24 bits, so 2 to the power 24 = 16,777,216 possible colours, and a pixel of an ordinary picture takes 3 bytes. The related term Pixel means the smallest dot in an image.

Real-world applications

  • Web design: colour codes like #FF8000 in CSS are hexadecimal RGB numbers.
  • Networking: MAC and IPv6 addresses are written in hex because it is compact.
  • Multilingual messaging: UTF-8 lets Arabic, English and symbols share one file.

Common mistakes

  • “A computer understands letters and pictures directly”: it handles only numbers, and meaning comes from the encoding we agree on.
  • “Binary means a computer only knows true and false”: one bit is two states, but grouping bits represents numbers and data without a practical limit.
  • “The character 5 is the number 5”: the character is a symbol with a code (53 in ASCII), while the number 5 is a value stored differently.
  • “Every character is exactly one byte”: true only for ASCII; in UTF-8 a character can take from one to four bytes.

Show solution

200 = 128 + 64 + 8, that is 11001000. By division: 200÷2=100 (0), 100÷2=50 (0), 50÷2=25 (0), 25÷2=12 (1), 12÷2=6 (0), 6÷2=3 (0), 3÷2=1 (1), 1÷2=0 (1); reading from the bottom gives 11001000. Split into 1100 and 1000, which are C and 8, so hex is C8; check: 12 × 16 + 8 = 200. As for 11010110, it is 128 + 64 + 16 + 4 + 2 = 214.

Exercise Reasoning: how many bytes does the text Hi € occupy in UTF-8, and why does it differ from the character count?
Show solution

The text has four characters: H is one byte, i is one byte, the space is one byte, and € is three bytes (E2 82 AC). The total is 1 + 1 + 1 + 3 = 6 bytes for four characters. UTF-8 is variable-length: English characters use a single byte while the others need more to cover the huge number of Unicode characters.

Exercise Hands-on: discover for yourself how your name is encoded as numbers using Python or a similar tool.
Show solution

Open the Python interpreter and type [ord(c) for c in "Sara"] to get [83, 97, 114, 97], the ASCII numbers of the letters. Then try "Sara".encode("utf-8") to see the same bytes. For an Arabic name each letter gives a large number (for example 1593 for the letter ain) and encode("utf-8") yields two bytes per letter. Compare the number of characters with the number of bytes.

Summary

  • A computer stores everything as binary numbers because circuits distinguish two states reliably.
  • Binary and decimal convert by adding powers or by repeated division, and hex is a shorthand for every four bits.
  • Text is numbers in ASCII or Unicode, and UTF-8 stores them with variable length.
  • A colour is three RGB bytes, giving 16,777,216 possibilities.
