Processes and Threads

Learning objectives

  • Distinguish a program from a process.
  • Know the process states and life cycle.
  • Compare a process with a thread.

Program versus process

A program is a static file on disk holding instructions. A process is one running instance of it: it has its own memory, open files and an identifier, the PID. Run the same program twice and you get two separate processes.

What does the kernel keep for each process? A table called the PCB (Process Control Block): the PID, the process state, the CPU register values, memory information and the open files.

Process states

StateMeaning
NewJust being created
ReadyReady and waiting for a CPU turn
RunningExecuting instructions right now
WaitingWaiting for an event such as a disk read or a key press
TerminatedFinished; its resources are released

Threads

One process may contain several threads: execution paths that share the same memory and files but each have their own stack and registers. A browser, for example, uses one thread to draw the page and another to download images, so the interface does not freeze.

ComparisonProcessThread
MemorySeparate and isolatedShared within the process
Creation costHigherLower
Effect of a crashOnly it crashesCan take down the whole process
CommunicationNeeds IPC (pipes, sockets)Directly through shared memory

Common mistakes

  • Saying a process and a program are the same thing.
  • Assuming more threads is always faster; a CPU has a limited number of cores.
Exercise You started the same editor three times. How many programs and how many processes do you have?
Show solution

One program (one file on disk) and three processes, each with its own PID and separate memory.

Summary

  • A process is a running program plus its resources.
  • The kernel tracks it through a PCB and well-defined states.
  • Threads share the process memory and enable concurrency.

Next step: Who decides which process gets the CPU now? Scheduling.

Core concept

A process is an isolated container for execution; a thread is a path of execution inside it.

Hands-on practice

Try it yourself

Open your system monitor and find the total process and thread counts, then pick one process and write down how many threads it has.

Test yourself

  1. What happens when a system call is made?

    • Execution moves into the kernel with higher privilege, then returns
    • The machine restarts
    • The program is deleted
    • The program bypasses the system and reaches the hardware
    Answer and explanation

    Correct answer: Execution moves into the kernel with higher privilege, then returns

  2. What role does the number 3 play in openat(...) = 3?

    • The file size in bytes
    • A file descriptor the kernel gives to the open file
    • The process PID
    • An error code
    Answer and explanation

    Correct answer: A file descriptor the kernel gives to the open file

    The descriptor is a handle later calls like read and close use to refer to the file.

  3. What is wrong with the statement: the shell is part of the kernel?

    • Nothing is wrong
    • The shell is an ordinary User Space program that asks the kernel to run programs
    • The shell is hardware
    • The shell always runs in Kernel Mode
    Answer and explanation

    Correct answer: The shell is an ordinary User Space program that asks the kernel to run programs

    The shell is an application like any other, text-based like Bash or graphical like a desktop.

  4. Which order is correct when reading a file?

    • Kernel reads, then library calls, then the application
    • The app calls a library function, then the trap instruction, then the kernel checks and reads, then data returns
    • The app reads the disk directly then tells the kernel
    • Trap first, then the app, then the library
    Answer and explanation

    Correct answer: The app calls a library function, then the trap instruction, then the kernel checks and reads, then data returns

    A special CPU instruction enters kernel mode, and the kernel checks permissions before reading.

  5. Why do libraries batch small operations (buffering)?

    • Because a system call is slower than a normal function call, so entries into the kernel are reduced
    • Because the kernel accepts only one byte
    • To hide files from the user
    • To increase the number of system calls
    Answer and explanation

    Correct answer: Because a system call is slower than a normal function call, so entries into the kernel are reduced

    Each kernel entry has a cost, so batching lowers it.
