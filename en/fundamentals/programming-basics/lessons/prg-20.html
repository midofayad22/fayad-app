Practice

Challenge yourself

Test yourself

  1. What is the most important thing to take away from this track?

    • Memorizing all Syntax
    • Logical thinking and problem solving
    • Memorizing language names
    • Writing the largest number of lines
    Answer and explanation

    Correct answer: Logical thinking and problem solving

  2. What is the output? function sumTo(n) { let s = 0; for (let i = 1; i <= n; i++) { s += i; } return s; } console.log(sumTo(4) + sumTo(2));

    • 13
    • 10
    • 16
    • 9
    Answer and explanation

    Correct answer: 13

    sumTo(4) = 1+2+3+4 = 10 and sumTo(2) = 1+2 = 3, giving 13 in total. Each call has its own s that starts at zero.

  3. What is the output? const items = [3, 8, 5]; let max = items[0]; for (const x of items) { if (x > max) max = x; } console.log(max);

    • 3
    • 16
    • 8
    • 5
    Answer and explanation

    Correct answer: 8

    max starts at 3 and becomes 8 at the second item; 5 is not greater than 8, so it stays 8. The loop combines a condition and an array in the find-the-maximum pattern.

  4. function isAdult(age) { if (age > 18) return true; return false; } A user who is exactly 18 is rejected. What is the fix?

    • Replace > with >= so that 18 is included
    • Replace return with console.log
    • Change 18 to 17.5 and delete the function
    • Add a loop inside the function
    Answer and explanation

    Correct answer: Replace > with >= so that 18 is included

    The comparison > excludes 18 itself, a boundary logic error. >= makes the condition true for everyone aged 18 and over.

  5. You want to build a new feature in your project. Which order applies what this track taught?

    • Write all the code, test on the last day, then save the version
    • Understand the task, split it, write a small part, test it, fix it, then commit
    • Commit first, then think
    • Remove the tests so bugs do not show
    Answer and explanation

    Correct answer: Understand the task, split it, write a small part, test it, fix it, then commit

    Working in small pieces with frequent testing exposes bugs early while their cause is near. Late testing piles up many bugs that are hard to separate.
