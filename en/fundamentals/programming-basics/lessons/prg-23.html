Time Complexity and Big-O

Open the interactive lesson (editor + quiz + progress)The exercise, quiz and progress tracking run on the interactive page.

COMPLEXITY

How does running time change as the data grows?

Learning objectives

  • Understand what O(n) and O(n²) mean.
  • Compare two solutions to the same problem.
  • Improve a slow solution using a suitable structure.

Prerequisites

  • The Loops (prg-11) and data structures (prg-22) lessons.

We do not measure in seconds

Running time in seconds changes with the machine. So we describe an algorithm by how the number of steps grows with input size n. That is Big-O: an approximate upper bound on growth that ignores constants.

NotationNameExample
O(1)ConstantReading an element by index list[3]
O(log n)LogarithmicBinary search
O(n)LinearVisiting each element once
O(n²)QuadraticA loop inside a loop over the same data

Example: finding a duplicate

With 1,000 items the first solution makes about half a million comparisons and the second only a thousand steps. With a million items the first becomes impractical (about 500 billion comparisons) while the second stays fast.

Common mistakes

  • Optimising before measuring the problem (premature optimisation).
  • Believing O(n²) is always bad; for tiny data it can be enough and clearer.
Exercise What is the complexity of two consecutive (not nested) loops of n items each?
Show solution

O(n): we add n + n = 2n, and the constant 2 is ignored in Big-O.

Summary

  • Big-O describes the growth of steps, not seconds.
  • A loop inside a loop is usually O(n²).
  • The right structure can turn O(n²) into O(n).

Next step: Different ways of thinking in programming: paradigms.

Core idea

A good algorithm is one whose running time stays acceptable when the data grows.

Worked example

See the idea in code

JavaScript 
const data = Array.from({ length: 5 }, (_, i) => i * 2);
let steps = 0;
for (const x of data) { steps++; }
console.log("n =", data.length, "steps =", steps);
Practice

Challenge yourself

Interactive exercise

Write hasDuplicate(arr) in O(n) using a Set. It is tested on 200,000 items; a quadratic solution will time out.

Test yourself

  1. What is the complexity of one for loop over n items?

    • O(n)
    • O(1)
    • O(n²)
    • O(log n)
    Answer and explanation

    Correct answer: O(n)

    The number of steps grows in proportion to n.

  2. What is the complexity of two nested loops over n items?

    • O(n²)
    • O(n)
    • O(1)
    • O(2n)
    Answer and explanation

    Correct answer: O(n²)

    For each outer item we visit n inner items.

  3. Why do we ignore constants in Big-O?

    • Because what matters is the growth shape at large sizes
    • Because they are wrong
    • Because the computer does not count them
    • No reason
    Answer and explanation

    Correct answer: Because what matters is the growth shape at large sizes

    At large n the growth shape dominates the constant.

  4. What does the Set do in hasDuplicateFast?

    • It makes checking for a value fast
    • It sorts the array
    • It deletes the array
    • It prints the result
    Answer and explanation

    Correct answer: It makes checking for a value fast

    has() does not scan all elements.

  5. What is the complexity of this code in terms of n? for (const x of arr) { f(x); } followed directly (not inside it) by for (const y of arr) { g(y); }

    • O(n)
    • O(n squared)
    • O(1)
    • O(log n)
    Answer and explanation

    Correct answer: O(n)

    The loops run one after the other, so the work is n + n = 2n, which is O(n) after dropping the constant. Squaring happens only when loops are nested.
