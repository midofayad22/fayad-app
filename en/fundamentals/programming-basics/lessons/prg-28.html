Project: A Tiny Calculator Language

Open the interactive lesson (editor + quiz + progress)The exercise, quiz and progress tracking run on the interactive page.

PROJECT

Tokenizer, parser and evaluator in one program

Learning objectives

  • Combine the three stages into a complete interpreter.
  • Add a new language feature (a new operator).
  • Understand how a language is designed from scratch.

Prerequisites

  • Lessons 21 to 27 of this section.

The goal

We build a function calc(text) that takes a text expression such as "2 + 3 * (4 - 1)" and returns its value. This is the heart of any interpreter: text, tokens, AST, value.

The complete program

Extending the language

Adding a feature goes through the same stages: the tokenizer must know the symbol, the parser must know where it fits in the grammar, and the evaluator must know its meaning. To add the remainder operator %, for example, we place it in the term level with * and / and add its case to evaluate.

Common mistakes

  • Adding the operator to evaluate only, so it is never even read.
  • Division by zero: in JavaScript it gives Infinity, and your language may want an error message.
Exercise Where would you put the power operator ^ so that it binds tighter than multiplication?
Show solution

In a new rule between term and factor: power := factor ("^" factor)*, and make term call power instead of factor.

Summary

  • An interpreter is a tokenizer, a parser and an evaluator.
  • Every new feature touches all three stages.
  • You built a real small language.

Next step: Try the extension ideas: big languages do the same thing with larger grammars.

Core idea

Every programming language, however big, is text, then tokens, then an AST, then execution.

Worked example

See the idea in code

JavaScript 
function tokenize(s) { return s.match(/\d+|[-+*/()]/g) || []; }
const tokens = tokenize("2 + 3 * 4");
console.log(tokens.length, tokens.join(" "));
Practice

Challenge yourself

Interactive exercise

The interpreter in the editor works but does not know the remainder %. Add support in all three stages so that calc("10 % 3") returns 1 and calc("2 + 7 % 4 * 3") returns 11.

Test yourself

  1. What are the three stages of the calculator interpreter?

    • Tokenize, parse, evaluate
    • Print, save, delete
    • Read, draw, play
    • Compile, ship, sell
    Answer and explanation

    Correct answer: Tokenize, parse, evaluate

    Text to tokens to tree to value.

  2. Where do you put % in the grammar?

    • In the term level with * and /
    • In the expression level with +
    • Inside numbers
    • Outside the language
    Answer and explanation

    Correct answer: In the term level with * and /

    Remainder has the same precedence as multiplication and division.

  3. What happens if we add % to evaluate only?

    • It is never read because the tokenizer does not know it
    • It works automatically
    • The computer crashes
    • The language is deleted
    Answer and explanation

    Correct answer: It is never read because the tokenizer does not know it

    The stages are linked: the symbol must pass through all three.

  4. What does calc("2 + 3 * (4 - 1)") return?

    • 11
    • 15
    • 9
    • 14
    Answer and explanation

    Correct answer: 11

    (4 - 1) = 3, then 3 × 3 = 9, then 2 + 9 = 11.

  5. What does calc("8 - 3 - 2") return with the parser that uses a while loop in expression?

    • 3
    • 7
    • -3
    • 13
    Answer and explanation

    Correct answer: 3

    The loop builds the tree from the left: (8 - 3) - 2 = 3. A right-leaning tree would give 8 - (3 - 2) = 7, which is wrong because subtraction associates from the left.
