What is an Algorithm?

An algorithm is a set of ordered, well-defined steps used to solve a problem or perform a task.

An algorithm does not have to be written in a programming language. It can be written in words or drawn as a Flowchart and later converted into code.

Example

Input

Two numbers the user wants to add.

Process

Performing the addition.

Output

Showing the result to the user.

Core idea

An algorithm describes the method of solving, while code translates that method into a language the computer can execute.

Worked example

See the idea in code

JavaScript 
let a = 10;
let b = 20;
let sum = a + b;
console.log(sum);
Practice

Challenge yourself

Test yourself

  1. What does an algorithm describe?

    • The color of the website
    • The steps for solving a problem
    • The type of screen
    • The file size
    Answer and explanation

    Correct answer: The steps for solving a problem

  2. Which of the following is a proper algorithm?

    • Be careful when crossing the street
    • Look left, then right; if there are no cars, cross, otherwise wait and look again
    • Cross in the best way possible
    • Think about safety
    Answer and explanation

    Correct answer: Look left, then right; if there are no cars, cross, otherwise wait and look again

    An algorithm is a set of definite, ordered, executable steps that ends with a result. The other sentences are vague advice that cannot be followed literally.

  3. The algorithm: set best to the first number, then for each other number, if it is bigger than best make it the new best. What is best for the input 4, 11, 7, 11, 2?

    • 4
    • 7
    • 22
    • 11
    Answer and explanation

    Correct answer: 11

    best starts at 4, becomes 11 at the second number, and never changes after that because no number is greater than 11 (the second 11 is not bigger). Starting with the first number does not make it the maximum.

  4. We start with n = 5 and repeat: add 1 to n until n becomes negative. What is the problem with this algorithm?

    • It never ends, violating the rule that an algorithm finishes after a finite number of steps
    • It needs very little memory
    • The number 5 is not allowed
    • Addition is not allowed in algorithms
    Answer and explanation

    Correct answer: It never ends, violating the rule that an algorithm finishes after a finite number of steps

    Adding 1 only makes n bigger, so it never becomes negative and the steps repeat forever. A correct algorithm must stop.

  5. To find a name in a sorted list of 1000 names, why is binary search better than checking names one by one?

    • Because it checks only about 10 names in the worst case instead of 1000, discarding half the list each time
    • Because it also works on unsorted lists
    • Because it guesses the name's location without checking
    • Because it always finds the name on the first step
    Answer and explanation

    Correct answer: Because it checks only about 10 names in the worst case instead of 1000, discarding half the list each time

    Binary search halves the search space each step, so 1000 items need about 10 steps, but it requires a sorted list. The claim that it works on unsorted lists is wrong.
