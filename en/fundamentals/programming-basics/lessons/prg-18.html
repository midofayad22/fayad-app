PROBLEM SOLVING

This is the skill that makes a programmer

Don't jump to the solution

When you face a programming problem, don't start by trying random code. Use a clear approach.

01

Understand the problem well.

02

Identify the inputs and outputs.

03

Break the problem into parts.

04

Design an Algorithm.

05

Turn the solution into Code.

06

Test and adjust.

Core idea

The better your problem-solving ability becomes, the more easily you can learn new languages and technologies.

Practice

Challenge yourself

Test yourself

  1. Which step comes before writing code?

    • Buying a computer
    • Understanding the problem and designing the solution
    • Opening GitHub
    • Choosing a color
    Answer and explanation

    Correct answer: Understanding the problem and designing the solution

  2. The task: write a function that finds the second largest number in a list. What is the best first step?

    • Write the loops right away and hope
    • Copy any code that looks similar
    • Understand the task with examples and edge cases such as duplicates and a one-item list
    • Only choose the function's name
    Answer and explanation

    Correct answer: Understand the task with examples and edge cases such as duplicates and a one-item list

    Understanding first decides what second largest means with duplicates such as [5,5,3]. Starting with code before clarity solves the wrong problem.

  3. You have been stuck on a bug for two hours in a big program. Which approach fits best?

    • Add more lines around the problem
    • Reduce it to the smallest example that reproduces the error, then explain its steps out loud
    • Just restart the computer
    • Delete the tests
    Answer and explanation

    Correct answer: Reduce it to the smallest example that reproduces the error, then explain its steps out loud

    A smaller example removes noise and exposes the cause, and explaining steps aloud reveals wrong assumptions. Adding lines only complicates the problem.

  4. Why is it useful to write the steps in plain words (pseudocode) before coding?

    • Because the computer understands plain words
    • Because it replaces testing
    • Because it makes the code faster
    • Because it separates thinking about the solution from syntax details, so flaws in the idea show up early
    Answer and explanation

    Correct answer: Because it separates thinking about the solution from syntax details, so flaws in the idea show up early

    Flaws in the idea are much cheaper to fix in the plan than after the code is written. The computer cannot run pseudocode and it does not replace testing.

  5. You wrote a function that computes the average of a list. Which set of tests is best?

    • A normal list only
    • A normal list, an empty list, a one-item list and a list with a negative number
    • The same normal list five times
    • No tests because the code looked correct
    Answer and explanation

    Correct answer: A normal list, an empty list, a one-item list and a list with a negative number

    Edge cases such as the empty list reveal problems like division by zero. Repeating the same test adds no new information.
