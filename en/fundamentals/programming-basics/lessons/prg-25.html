How Languages Work: Compilers and Interpreters

COMPILERS

From the text you write to what the CPU runs

Learning objectives

  • Explain the difference between a compiler and an interpreter.
  • Know the stages of processing source code.
  • Understand bytecode and a virtual machine.

Prerequisites

  • Lessons: What is programming (prg-01), How code runs (prg-02), Programming languages (prg-05).

The CPU does not understand JavaScript

The CPU only runs simple binary instructions (machine code). Program text is written for humans, so some program has to translate it. There are two main ways:

AspectCompilerInterpreter
HowTranslates the whole program before running into an executableReads and executes the code step by step
SpeedUsually faster executionUsually slower but starts instantly
ErrorsReported before runningMay appear while running
ExamplesC, Rust and GoPython and Ruby (traditionally)

The processing stages

The journey of one statement through every stage

In this section we build a small language called FAY. Take this statement from our language: let area = 3 * (2 + 4). Watch how the shape of the data changes at every stage, and how each stage takes only the output of the previous one:

StageReceivesProducesWhat changed?
1. Source code—text: let area = 3 * (2 + 4)a string of characters with no meaning to the machine
2. Tokenizerthe texta list: let area = 3 * ( 2 + 4 )characters grouped into typed units
3. Parserthe token listan ASTstructure and precedence appeared; the brackets vanished because the tree carries their meaning
4. Interpreterthe treean environment: area = 18the arithmetic ran and the value was stored in memory
5. Outputthe environmentprint area gives 18something the user sees

Bytecode and a virtual machine

Bytecode is a simple intermediate instruction set that no real CPU understands, but a program called a virtual machine does. That is the idea behind the JVM and CPython. A stack machine is among the simplest kinds; it runs the expression 2 + 3 like this:

Common mistakes

  • Saying a language itself is “compiled” or “interpreted”: that describes an implementation, not the language.
  • Believing an interpreter is necessarily slow.
Exercise Why do syntax errors in a compiled language reach you before the program runs?
Show solution

Because the compiler analyses the whole program during translation, so it finds syntax and semantic errors before producing the executable.

Summary

  • A compiler translates before running; an interpreter executes while reading.
  • Stages: lexer, parser, analysis, execution.
  • Bytecode runs on a virtual machine.

Next step: We build the first stage ourselves: the tokenizer.

Core idea

Every language goes through stages from text to execution, and understanding them removes the mystery.

Worked example

See the idea in code

JavaScript 
// a tiny stack machine
const program = ["push 4", "push 5", "mul"];
const stack = [];
for (const line of program) {
const [op, arg] = line.split(" ");
if (op === "push") stack.push(Number(arg));
if (op === "mul") stack.push(stack.pop() * stack.pop());
}
console.log(stack.pop());

Test yourself

  1. What is the main difference between a compiler and an interpreter?

    • A compiler translates before running; an interpreter executes while reading
    • A compiler is cheaper
    • There is no difference
    • An interpreter needs no code
    Answer and explanation

    Correct answer: A compiler translates before running; an interpreter executes while reading

    This is the core difference, although modern implementations mix both.

  2. What runs bytecode?

    • A virtual machine
    • The hard disk
    • The keyboard
    • The screen
    Answer and explanation

    Correct answer: A virtual machine

    A virtual machine is a program that simulates a simple processor.

  3. Which stage splits the text into tokens?

    • The lexer
    • The parser
    • The linker
    • The debugger
    Answer and explanation

    Correct answer: The lexer

    The lexical analyser is the first stage.

  4. What does the stack machine produce for push 4, push 5, mul?

    • 20
    • 9
    • 45
    • 1
    Answer and explanation

    Correct answer: 20

    4 × 5 = 20.

  5. What is the stack machine's final result? push 10, push 3, push 2, mul, sub (sub subtracts the top item from the deeper one)

    • 5
    • 4
    • -4
    • 60
    Answer and explanation

    Correct answer: 4

    After the pushes the stack is [10,3,2]; mul replaces 3 and 2 with 6 giving [10,6]; then sub gives 10 - 6 = 4. Operand order matters because subtraction is not commutative.
