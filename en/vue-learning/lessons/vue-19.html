Lifecycle Hooks

Vue components go through different stages during their life.

Lifecycle hooks let you run logic at specific stages, such as the moment the component is mounted.

Hooks run at specific stages

You can run logic when important stages in a component's lifecycle occur.

Code example

The code


<div id="app">
<h2>Hello Vue</h2>
</div>
<script>
const { createApp, onMounted } = Vue;
createApp({
setup() {
onMounted(() => {
console.log("Component mounted!");
});
}
}).mount("#app");
</script>
Hello Vue

onMounted ran after the component was mounted.

Understanding the code

onMounted() is a lifecycle hook from the Composition API.

The callback runs after the component is mounted in the DOM.

Other hooks exist, such as onUpdated() and onUnmounted().

Try it yourself

Test yourself

  1. When does onMounted() run?

    • After the component is mounted
    • Before JavaScript loads
    • Only when CSS changes
    • When HTML is deleted
    Answer and explanation

    Correct answer: After the component is mounted

  2. What do lifecycle hooks do?

    • Run logic at specific stages of a component's life
    • Create databases
    • Change the operating system
    • Create images
    Answer and explanation

    Correct answer: Run logic at specific stages of a component's life

  3. Which hook is used to run logic after mounting?

    • onMounted()
    • onStarted()
    • onLoadedCSS()
    • afterVue()
    Answer and explanation

    Correct answer: onMounted()

  4. Where do we put a data fetch we want to run when the component appears on the page?

    • Inside onMounted
    • Inside <style>
    • After the component is removed
    • Inside the props
    Answer and explanation

    Correct answer: Inside onMounted

    onMounted runs after the component is inserted into the DOM and is a common place for initial data fetching.

  5. Which hook is suitable for clearing a setInterval before the component is removed?

    • onMounted
    • onUpdated
    • onBeforeUnmount
    • watch
    Answer and explanation

    Correct answer: onBeforeUnmount

    onBeforeUnmount runs just before removal, so we stop timers and listeners there to avoid leaks.
