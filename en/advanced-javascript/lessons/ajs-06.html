Prototypes and the Inheritance Chain

How inheritance actually works in JavaScript through prototype objects.

Open the interactive lesson (editor + quiz + progress)The exercise, quiz and progress tracking run on the interactive page.

Prototype Chain

Every object has an internal link to another object, its prototype. When reading a property that does not exist, the engine searches the chain up to Object.prototype and then null.

Tools

  • Object.create(proto) creates an object with a direct link.
  • Object.getPrototypeOf(obj) reads the link.
  • hasOwn distinguishes an own property from an inherited one.

Inheritance in JavaScript is delegation along the chain, not copying of properties.

Code example

JavaScript code

const animal = {
speak() { return this.name + " makes a sound"; },
};
const dog = Object.create(animal);
dog.name = "Rex";
console.log(dog.speak());
console.log(Object.hasOwn(dog, "speak"), "speak" in dog);
console.log(Object.getPrototypeOf(dog) === animal);
function Person(name) { this.name = name; }
Person.prototype.hi = function () { return "hi " + this.name; };
const p = new Person("Mona");
console.log(p.hi(), p instanceof Person);
Rex makes a sound
false true
true
hi Mona true

Understanding the code

speak does not exist on dog itself, so hasOwn returns false, but the in operator searches the chain and returns true. Constructor functions put methods on prototype to share them among all objects.

Test yourself

  1. How does the engine look for a property that does not exist on the object?

    • It follows the prototype chain until null
    • It throws an error immediately
    • It searches only the global scope
    • It creates it automatically
    Answer and explanation

    Correct answer: It follows the prototype chain until null

  2. What does Object.hasOwn do?

    • Checks that the property exists on the object itself, not inherited
    • Deletes the property
    • Copies the object
    • Searches the whole chain
    Answer and explanation

    Correct answer: Checks that the property exists on the object itself, not inherited

  3. Where are shared methods placed in constructor functions?

    • On Constructor.prototype
    • Inside each object
    • In the global scope
    • In localStorage
    Answer and explanation

    Correct answer: On Constructor.prototype

  4. What does this code print? function A() {} A.prototype.hi = function () {}; const a = new A(); console.log(a.hasOwnProperty("hi"), "hi" in a);

    • true true
    • false true
    • true false
    • false false
    Answer and explanation

    Correct answer: false true

    hi lives on A.prototype and is not an own property of a, so hasOwnProperty gives false. The in operator also searches the prototype chain, so it gives true.

  5. What does console.log("toString" in Object.create(null)) print?

    • true, because every object inherits toString
    • undefined
    • A TypeError
    • false, because the object has no prototype and inherits nothing
    Answer and explanation

    Correct answer: false, because the object has no prototype and inherits nothing

    Object.create(null) creates an object with no prototype, so properties of Object.prototype such as toString never reach it. That makes it a clean dictionary free of inherited keys.
