Memoization, Debounce, and Throttle

Practical performance techniques: caching results and limiting the number of calls.

Open the interactive lesson (editor + quiz + progress)The exercise, quiz and progress tracking run on the interactive page.

Memoization

Store the result of a pure function for each input so it is not computed twice. The key is usually derived from the inputs.

Debounce and Throttle

Debounce runs the function after calls have stopped for a set period (such as search-as-you-type). Throttle runs it at most once per interval (such as scrolling).

Memoization is for pure functions only, and Debounce delays while Throttle limits.

Code example

JavaScript code

const memo = (fn) => {
const cache = new Map();
return (n) => {
if (cache.has(n)) return cache.get(n);
const v = fn(n);
cache.set(n, v);
return v;
};
};
let calls = 0;
const square = memo((n) => { calls++; return n * n; });
square(4); square(4); square(5);
console.log("calls:", calls);
const debounce = (fn, ms) => {
let t;
return (...a) => {
clearTimeout(t);
t = setTimeout(() => fn(...a), ms);
};
};
const log = debounce((v) => console.log("saved", v), 20);
log("a"); log("b"); log("c");
calls: 2
saved c

Understanding the code

The second call to square(4) came from the cache, so the counter did not increase. In debounce, each call cancels the previous timer so only the last one runs.

Test yourself

  1. When is Memoization safe?

    • With pure functions that do not depend on external state
    • With any function
    • With asynchronous functions only
    • It is never safe
    Answer and explanation

    Correct answer: With pure functions that do not depend on external state

  2. What does Debounce do?

    • Delays execution until the calls stop
    • Runs every call immediately
    • Blocks the function permanently
    • Repeats the function
    Answer and explanation

    Correct answer: Delays execution until the calls stop

  3. Which technique suits the frequently firing scroll event?

    • Throttle
    • Memoization
    • Currying
    • Hoisting
    Answer and explanation

    Correct answer: Throttle

  4. A memoize helper caches results by args[0] only. What goes wrong when it wraps add(a, b)?

    • add(1, 2) then add(1, 5) returns the stale 3 from the cache for the second call
    • The cache cannot work with two-parameter functions
    • The function always becomes slower
    • No problem, the first argument is always enough
    Answer and explanation

    Correct answer: add(1, 2) then add(1, 5) returns the stale 3 from the cache for the second call

    The cache key must represent every input that affects the result, otherwise keys collide and stale wrong results are returned. Build the key from all args, for example JSON.stringify(args).

  5. A debounced function with a 200ms wait is called at 0, 50 and 100ms. When and how many times does the original run?

    • Three times at 200, 250 and 300
    • Once at 200ms
    • Once at 300ms
    • Twice at 0 and 100
    Answer and explanation

    Correct answer: Once at 300ms

    Each new call cancels the previous timer and starts a fresh wait. The last call was at 100ms, so the function runs once, 200ms later, at 300ms.
