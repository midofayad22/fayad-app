AbortController and Async Iterators

Cancel in-flight operations and read asynchronous streams with for await...of.

Open the interactive lesson (editor + quiz + progress)The exercise, quiz and progress tracking run on the interactive page.

Cancelling Operations

AbortController produces a signal that you pass to the operation (such as fetch). Calling abort() makes the operation reject with an AbortError and stop.

Async Iterators

The async generator async function* produces values over time, and we read it with for await...of. It suits streams and successive pages.

Pass the signal and check it, and treat cancellation as a normal case, not a surprise error.

Code example

JavaScript code

const sleep = (ms, signal) => new Promise((resolve, reject) => {
const t = setTimeout(resolve, ms);
signal?.addEventListener("abort", () => {
clearTimeout(t);
reject(signal.reason);
});
});
(async () => {
const ctrl = new AbortController();
setTimeout(() => ctrl.abort(new Error("cancelled")), 10);
try { await sleep(200, ctrl.signal); }
catch (e) { console.log(e.message); }
async function* pages() {
for (let p = 1; p <= 3; p++) {
await sleep(5);
yield [p * 10, p * 10 + 1];
}
}
const all = [];
for await (const items of pages()) all.push(...items);
console.log(all);
})();
cancelled
[ 10, 11, 20, 21, 30, 31 ]

Understanding the code

Cancellation avoids waiting the full time (200ms). The async generator hands out successive pages, and for await waits for each page before moving to the next.

    Answer and explanation

  4. What is the output? const c = new AbortController(); c.signal.addEventListener("abort", () => console.log("ab")); c.abort(); c.abort(); console.log(c.signal.aborted);

    • ab, ab, true
    • ab, true
    • true only
    • An error on the second call
    Answer and explanation

    Correct answer: ab, true

    Aborting happens only once, and later abort calls do nothing and do not fire the event again. Afterwards signal.aborted is true.

  5. What is printed? async function* g() { try { yield 1; yield 2; } finally { console.log("cleanup"); } } (async () => { for await (const x of g()) { console.log(x); break; } })();

    • 1 only
    • 1, 2, cleanup
    • 1, cleanup
    • cleanup, 1
    Answer and explanation

    Correct answer: 1, cleanup

    Leaving for await early with break calls the generator's return, which runs the finally block and prints cleanup after 1. That is why cleanup belongs in finally, so it runs even on early exit.
