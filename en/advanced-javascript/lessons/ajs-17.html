Practical async/await Patterns

Sequential versus parallel execution, retrying, timeouts, and correct error handling.

Open the interactive lesson (editor + quiz + progress)The exercise, quiz and progress tracking run on the interactive page.

Sequential or Parallel?

Using await inside a loop runs operations one after another. If they are independent, start them all and then await them together with Promise.all to save time.

Retry and Timeout

Many network operations fail temporarily. Write a retry function with a set number of attempts, and a race against a timer to enforce a timeout.

Do not put await inside a loop if the operations are independent.

Code example

JavaScript code

const wait = (ms, v) => new Promise((r) => setTimeout(() => r(v), ms));
async function retry(fn, times) {
let lastError;
for (let i = 1; i <= times; i++) {
try { return await fn(i); }
catch (e) { lastError = e; console.log("attempt", i, "failed"); }
}
throw lastError;
}
const withTimeout = (p, ms) =>
Promise.race([p, new Promise((_, j) => setTimeout(() => j(new Error("timeout")), ms))]);
(async () => {
const v = await retry(async (n) => { if (n < 3) throw new Error("flaky"); return "ok on " + n; }, 5);
console.log(v);
const t0 = Date.now();
await Promise.all([wait(40), wait(40), wait(40)]);
console.log("parallel under 110ms:", Date.now() - t0 < 110);
try { await withTimeout(wait(100), 10); } catch (e) { console.log(e.message); }
})();
attempt 1 failed
attempt 2 failed
ok on 3
parallel under 110ms: true
timeout

Understanding the code

Three 40ms waits finish together in ~40ms, not 120ms, because they started at the same time. The retry function keeps the last error and throws it if the attempts are exhausted.

    • setTimeout only
    • console.log
    • typeof
    Answer and explanation

    Correct answer: Promise.race with a promise that rejects after the timeout

  3. What is the purpose of retry?

    • Retrying the operation on a temporary failure
    • Speeding up the browser
    • Deleting errors
    • Always creating a new Promise
    Answer and explanation

    Correct answer: Retrying the operation on a temporary failure

  4. What is the print order? [1, 2].forEach(async n => { await null; console.log(n); }); console.log("end");

    • 1, 2, end
    • end, 1, 2
    • end only
    • 1, end, 2
    Answer and explanation

    Correct answer: end, 1, 2

    forEach does not wait for the promises returned by async callbacks, so it finishes immediately and end prints first. For real waiting use for...of with await, or Promise.all with map.

  5. What does this code print? async function f() { try { return Promise.reject(new Error("x")); } catch { return "caught"; } } f().catch(e => console.log(e.message));

    • caught
    • x
    • Nothing
    • undefined
    Answer and explanation

    Correct answer: x

    return without await hands the rejected promise outward before try can catch it, so the inner catch never runs. With return await the catch would handle it and caught would print.
