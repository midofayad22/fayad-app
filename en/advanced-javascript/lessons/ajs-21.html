Design Patterns: Observer and Pub/Sub

Connect parts of the application without direct dependencies between them using event patterns.

Open the interactive lesson (editor + quiz + progress)The exercise, quiz and progress tracking run on the interactive page.

Observer / Pub-Sub

The source (Subject) publishes events and listeners subscribe to them without the source knowing who they are. This reduces coupling and makes testing and extension easier.

Beware of Leaks

Every subscription must have a way to cancel it (unsubscribe), otherwise the references remain in memory.

Every subscribe returns an unsubscribe function.

Code example

JavaScript code

function createStore(initial) {
let state = initial;
const listeners = new Set();
return {
get: () => state,
set(next) {
state = { ...state, ...next };
listeners.forEach((fn) => fn(state));
},
subscribe(fn) {
listeners.add(fn);
return () => listeners.delete(fn);
},
};
}
const store = createStore({ count: 0 });
const off = store.subscribe((s) => console.log("A sees", s.count));
store.subscribe((s) => console.log("B sees", s.count));
store.set({ count: 1 });
off();
store.set({ count: 2 });
A sees 1
B sees 1
B sees 2

Understanding the code

After calling off(), subscriber A no longer receives updates. Using a Set prevents registering the same function twice.

Test yourself

  1. What is the main advantage of the Pub/Sub pattern?

    • Reducing coupling between the publisher and the listeners
    • Speeding up the network
    • Encrypting data
    • Eliminating errors
    Answer and explanation

    Correct answer: Reducing coupling between the publisher and the listeners

  2. Why do we return a function from subscribe?

    • To unsubscribe and prevent memory leaks
    • To print the result
    • To repeat the event
    • To change the state
    Answer and explanation

    Correct answer: To unsubscribe and prevent memory leaks

  3. Why do we use a Set to store listeners?

    • To prevent duplicate listeners and make removal easy
    • Because Array does not exist
    • To encrypt them
    • To sort them alphabetically
    Answer and explanation

    Correct answer: To prevent duplicate listeners and make removal easy

  4. What does this code print? const s = new Set(); const l = () => console.log("x"); s.add(l); s.add(l); s.forEach(f => f());

    • x once, because a Set does not duplicate the same item
    • x twice
    • Nothing
    • An error on the second add
    Answer and explanation

    Correct answer: x once, because a Set does not duplicate the same item

    The listener registered twice is the same function, and a Set keeps one copy, so it is not run twice for the same event. That is why a Set suits storing subscribers.

  5. A UI component subscribed to a global event and was then removed from the page without unsubscribing. What is the result?

    • The subscription is cancelled automatically when the component is removed
    • The event is ignored by the platform
    • The callback stays registered, runs for a dead component and keeps its memory from being freed
    • The event throws an error every time
    Answer and explanation

    Correct answer: The callback stays registered, runs for a dead component and keeps its memory from being freed

    The publisher holds a reference to the callback and everything it captured from the component, so the garbage collector cannot free it and it keeps running. That is why we call the unsubscribe function during cleanup.
