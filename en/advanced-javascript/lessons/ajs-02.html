Closures

A function that remembers the scope it was born in: the foundation of privacy and hidden state in JavaScript.

Open the interactive lesson (editor + quiz + progress)The exercise, quiz and progress tracking run on the interactive page.

What Is a Closure?

A Closure is a function together with a reference to its lexical environment (the surrounding variables at the time it was defined). Those variables stay alive as long as the function can be called, even after the outer function has finished.

Practical Uses

  • Counters and private state that cannot be accessed from outside.
  • Function factories (Function Factories).
  • Event handlers that need data from the time of creation.

Every call to the outer function creates a new, independent environment, and the inner functions retain it.

Code example

JavaScript code

function makeCounter(start = 0) {
let count = start;
return {
inc: () => ++count,
value: () => count,
};
}
const a = makeCounter();
const b = makeCounter(10);
a.inc();
a.inc();
b.inc();
console.log(a.value(), b.value());
const fns = [];
for (var i = 0; i < 3; i++) fns.push(() => i);
console.log(fns.map((f) => f()));
const fns2 = [];
for (let j = 0; j < 3; j++) fns2.push(() => j);
console.log(fns2.map((f) => f()));
2 11
[ 3, 3, 3 ]
[ 0, 1, 2 ]

Understanding the code

Each counter has its own count. With var there is a single copy of i shared by everyone, so it becomes 3. With let, a new copy is created for each iteration.

  1. Why does a var loop with deferred functions give the same value?

    • Because there is a single shared variable in the function scope
    • Because var is slower
    • Because functions remember nothing
    • Because of a bug in the engine
    Answer and explanation

    Correct answer: Because there is a single shared variable in the function scope

  2. What does a Closure guarantee?

    • The surrounding variables remain available to the function
    • The function runs twice
    • Errors are prevented
    • The code runs faster
    Answer and explanation

    Correct answer: The surrounding variables remain available to the function

  3. How do we hide internal state from the outside?

    • By defining it inside a function and returning functions that alone use it
    • By naming it with a capital letter
    • By using console.log
    • It is not possible
    Answer and explanation

    Correct answer: By defining it inside a function and returning functions that alone use it

  4. What does this code print? const mk = () => { let c = 0; return () => ++c; }; const a = mk(), b = mk(); a(); a(); console.log(a(), b());

    • 3 and 1
    • 3 and 3
    • 1 and 1
    • 2 and 1
    Answer and explanation

    Correct answer: 3 and 1

    Each call to mk creates a new scope with its own c, kept alive by the returned function. So a counts alone up to 3, and b starts from 1.

  5. What does this code print? let n = 1; const f = () => n; n = 2; console.log(f());

    • 1, because the function copied the value when created
    • 2, because the closure keeps the variable itself, not a copy of its value
    • undefined
    • An error because n changed after creation
    Answer and explanation

    Correct answer: 2, because the closure keeps the variable itself, not a copy of its value

    A closure captures the binding to the variable, not its value at creation time, so it sees later changes. The current value 2 is read at call time.
