Scope, Hoisting, and the TDZ

Understand how the engine looks up variables, what actually happens during hoisting, and why the Temporal Dead Zone exists.

Open the interactive lesson (editor + quiz + progress)The exercise, quiz and progress tracking run on the interactive page.

Scope Chain

Every function and every { } block (with let and const) creates a scope. When a variable is read, the engine looks in the current scope, then in the parent scope, and so on up to the global scope. This chain is called the Scope Chain.

Hoisting and the TDZ

Declarations are hoisted to the top of their scope, but in different states: var starts with the value undefined, while let and const stay uninitialized until the declaration line, and any access before it throws a ReferenceError. This period is called the Temporal Dead Zone.

var is hoisted with the value undefined, while let/const are hoisted but cannot be used before the declaration line.

Code example

JavaScript code

console.log(typeof hoisted);
var hoisted = 1;
console.log(hoisted);
try {
console.log(late);
} catch (e) {
console.log(e.name);
}
let late = 2;
const x = "global";
function outer() {
const x = "outer";
function inner() {
return x;
}
return inner();
}
console.log(outer());
undefined
1
ReferenceError
outer

Understanding the code

The variable hoisted exists before its line with the value undefined. Reading late before its declaration throws a ReferenceError. And inner sees the x belonging to outer because it is the nearest scope in the chain.

  3. What is meant by the Scope Chain?

    • The chain of scopes the engine searches for a variable, from nearest to farthest
    • The execution order of functions
    • The list of errors
    • The order of files
    Answer and explanation

    Correct answer: The chain of scopes the engine searches for a variable, from nearest to farthest

  4. What does this code print? console.log(typeof f, typeof g); function f() {} var g = function () {};

    • undefined undefined
    • function function
    • A ReferenceError at g
    • function undefined
    Answer and explanation

    Correct answer: function undefined

    The declaration f is hoisted with its whole body, so its type is function. g is a var, so only the declaration is hoisted with the value undefined, and the function is assigned only when execution reaches that line.

  5. What happens? let x = 1; { console.log(x); let x = 2; }

    • It prints 1 because it uses the outer x
    • It prints undefined
    • It throws a ReferenceError because the inner x is in the TDZ until its declaration line
    • It prints 2
    Answer and explanation

    Correct answer: It throws a ReferenceError because the inner x is in the TDZ until its declaration line

    The inner let shadows the outer x for the whole block, but it cannot be read before its declaration, which is the TDZ. So the outer x is not used and the value is not undefined.
