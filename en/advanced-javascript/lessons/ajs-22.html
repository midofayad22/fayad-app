Performance and Memory

Algorithm complexity, avoiding common leaks, and measuring performance before optimizing.

Open the interactive lesson (editor + quiz + progress)The exercise, quiz and progress tracking run on the interactive page.

Think About Complexity

Searching an array is O(n) while Set.has and Map.get are roughly O(1). Replacing a lookup inside a loop with a Set can turn O(n²) into O(n).

Common Memory Leaks

  • Event listeners that were not removed.
  • setInterval timers that were not cleared.
  • Closures holding on to huge objects.
  • Global Maps that grow without limit (use WeakMap or a size limit).

Measure first, then optimize. Premature optimization without measurement wastes time.

Code example

JavaScript code

const N = 2000;
const a = Array.from({ length: N }, (_, i) => i);
const b = Array.from({ length: N }, (_, i) => i * 2);
function slow() {
let n = 0;
for (const x of a) if (b.includes(x)) n++;
return n;
}
function fast() {
const set = new Set(b);
let n = 0;
for (const x of a) if (set.has(x)) n++;
return n;
}
console.log(slow() === fast(), fast());
const cache = new Map();
function remember(key, value, max = 3) {
cache.set(key, value);
if (cache.size > max) cache.delete(cache.keys().next().value);
}
["a", "b", "c", "d", "e"].forEach((k, i) => remember(k, i));
console.log([...cache.keys()]);
true 1000
[ 'c', 'd', 'e' ]

Understanding the code

Both versions give the same result, but the second is much faster at large sizes. The bounded cache deletes the oldest key (Map preserves insertion order), so it does not grow without limit.

  1. What is the advantage of Set.has compared to includes?

    • Faster lookup (roughly constant time) on large collections
    • It automatically removes duplicates from the output
    • It works on strings only
    • There is never any difference
    Answer and explanation

    Correct answer: Faster lookup (roughly constant time) on large collections

  2. Which of the following is a common cause of memory leaks?

    • Event listeners that were not removed
    • Using const
    • Writing comments
    • Using map
    Answer and explanation

    Correct answer: Event listeners that were not removed

  3. What is the right rule for optimization?

    • Measure first, then optimize what is actually slowest
    • Optimize every line early
    • Never optimize
    • Write everything with nested loops
    Answer and explanation

    Correct answer: Measure first, then optimize what is actually slowest

  4. A loop writes an element's style and then reads offsetHeight on every iteration. What is the problem and the fix?

    • No problem, reading is always fast
    • Alternating writes and reads forces the browser to recompute layout on every iteration, so batch the reads first and then the writes
    • offsetHeight does not work inside loops
    • The fix is to use var instead of let
    Answer and explanation

    Correct answer: Alternating writes and reads forces the browser to recompute layout on every iteration, so batch the reads first and then the writes

    Reading a layout property after a related change forces a synchronous recalculation known as layout thrashing. Batching all reads first and then the writes lets the browser calculate once.

  5. A list has 1000 items that must each respond to a click. What is the most efficient approach?

    • Add a separate listener to each item
    • Use setInterval to poll for clicks
    • One listener on the container that checks event.target (event delegation)
    • Rebuild the page after every click
    Answer and explanation

    Correct answer: One listener on the container that checks event.target (event delegation)

    Events bubble up to the container, so one listener serves every item and also works for items added later. This saves memory and time compared with a thousand listeners.
