المعالج لا يفهم JavaScript

المعالج ينفّذ تعليمات ثنائية بسيطة فقط (لغة الآلة). أما نصوص البرامج فهي للبشر، فلا بد من برنامج يترجمها. وهناك طريقتان رئيسيتان:

الجانبCompilerInterpreter
الطريقةيترجم البرنامج كله قبل التشغيل إلى ملف تنفيذييقرأ ويُنفّذ الشيفرة خطوة بخطوة
السرعةتنفيذ أسرع عادةًأبطأ عادةً لكن بدء فوري
الأخطاءتظهر كلها قبل التشغيلقد تظهر أثناء التشغيل
أمثلةC وRust وGoPython وRuby (تقليديًا)

مراحل المعالجة

رحلة جملة واحدة عبر كل المراحل

سنبني في هذا القسم لغة صغيرة اسمها FAY. خذ هذه الجملة من لغتنا: let area = 3 * (2 + 4). لاحظ كيف يتغير شكل البيانات في كل مرحلة، وكيف تأخذ كل مرحلة ناتج التي قبلها فقط:

Bytecode وآلة افتراضية

Bytecode تعليمات وسيطة بسيطة لا يفهمها المعالج الحقيقي بل برنامج اسمه Virtual Machine. هذه فكرة JVM وCPython. الآلة المكدسية Stack Machine من أبسط أنواعها: تنفّذ التعبير 2 + 3 هكذا:

أخطاء شائعة

  • القول إن اللغة نفسها «مترجَمة» أو «مفسَّرة»: هذه صفة التنفيذ وليست صفة اللغة.
  • الاعتقاد أن المفسّر يعني بطيئًا بالضرورة.
تمرين لماذا تصلك أخطاء الصياغة في لغة مترجمة قبل أن يعمل البرنامج؟
عرض الحل

لأن الـ Compiler يحلل البرنامج كله في مرحلة الترجمة، فيكتشف الأخطاء النحوية والدلالية قبل إنتاج الملف التنفيذي.

الخلاصة

  • المترجم يترجم قبل التشغيل، والمفسّر ينفّذ أثناء القراءة.
  • المراحل: Lexer ثم Parser ثم تحليل ثم تنفيذ.
  • Bytecode تُنفَّذ على آلة افتراضية.

الخطوة التالية: نبني أول مرحلة بأيدينا: الـ Tokenizer.

الفكرة الأساسية

كل لغة تمر بمراحل تحويل من النص إلى تنفيذ، وفهمها يزيل الغموض عن «سحر» البرمجة.

مثال عملي

شاهد الفكرة في كود

JavaScript 
// a tiny stack machine
const program = ["push 4", "push 5", "mul"];
const stack = [];
for (const line of program) {
const [op, arg] = line.split(" ");
if (op === "push") stack.push(Number(arg));
if (op === "mul") stack.push(stack.pop() * stack.pop());
}
console.log(stack.pop());

تحدَّ نفسك

تمرين تفاعلي

أكمل الآلة المكدسية: اكتب run(program) تدعم push n وadd وmul وsub (الطرح: العنصر الأعمق ناقص الأعلى) وتعيد القيمة النهائية.

اختبر نفسك

  1. ما الفرق الأساسي بين المترجم والمفسّر؟

    • المترجم يترجم قبل التشغيل والمفسّر ينفّذ أثناء القراءة
    • المترجم أرخص
    • لا فرق
    • المفسّر لا يحتاج شيفرة
    الإجابة والشرح

    الإجابة الصحيحة: المترجم يترجم قبل التشغيل والمفسّر ينفّذ أثناء القراءة

    هذا هو الفرق الجوهري، مع أن التطبيقات الحديثة تمزج بينهما.

  2. ما الذي ينفّذ Bytecode؟

    • آلة افتراضية
    • القرص الصلب
    • لوحة المفاتيح
    • الشاشة
    الإجابة والشرح

    الإجابة الصحيحة: آلة افتراضية

    الآلة الافتراضية برنامج يحاكي معالجًا بسيطًا.

  3. ما المرحلة التي تقطّع النص إلى رموز؟

    • Lexer
    • Parser
    • Linker
    • Debugger
    الإجابة والشرح

    الإجابة الصحيحة: Lexer

    المحلل المعجمي هو أول مرحلة.

  4. ما ناتج الآلة المكدسية للبرنامج push 4 ثم push 5 ثم mul؟

    • 20
    • 9
    • 45
    • 1
    الإجابة والشرح

    الإجابة الصحيحة: 20

    4 × 5 = 20.

  5. ما الناتج النهائي للآلة المكدسية؟ push 10، push 3، push 2، mul، sub (sub يطرح العنصر الأعلى من الأعمق)

    • 5
    • 4
    • -4
    • 60
    الإجابة والشرح

    الإجابة الصحيحة: 4

    بعد الدفعات تكون المكدسة [10,3,2]، و mul تستبدل 3 و 2 بـ 6 فتصبح [10,6]، ثم sub تعطي 10 - 6 = 4. ترتيب المعاملات مهم لأن الطرح غير تبادلي.
