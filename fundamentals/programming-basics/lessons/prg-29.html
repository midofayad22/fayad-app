الأخطاء النحوية وتصحيحها

افتح الدرس التفاعلي (محرر + اختبار + تتبّع التقدم)يعمل التمرين والاختبار وحفظ التقدم في الصفحة التفاعلية.

DEBUGGING

كيف تكتشف اللغة الخطأ وكيف تتبّع مصدره

أهداف الدرس

  • تفرّق بين الخطأ المعجمي والنحوي ووقت التشغيل.
  • تفهم كيف يكتشف الـ Parser الخطأ ويذكر موضعه.
  • تتبّع مصدر المشكلة بفحص مخرجات كل مرحلة.

المتطلبات السابقة

  • دروس Tokenizer وParser (prg-26 وprg-27) ودرس Debugging (prg-17).

ثلاثة أنواع من الأخطاء

كل مرحلة في مفسّرنا ترى العالم بطريقتها، فتكتشف نوعًا مختلفًا من المشكلات. معرفة المرحلة التي رفضت الشيفرة تعني أنك عرفت نصف الحل.

كيف يكتشف الـ Parser الخطأ؟

الـ Parser يتوقع رمزًا معينًا في كل موضع. الدالة expect تفحص الرمز التالي: إن كان ما توقعته تابعت، وإلا رميت خطأ يذكر ما توقعته وأين حدث. فحصنا لـ (1 + 2 يسير هكذا:

طريقة منهجية لتتبّع المشكلة

  1. اطبع الـ Tokens: هل قُطّع النص كما توقعت؟ إن كان خطأ هنا فالمشكلة في الـ Tokenizer.
  2. اطبع الشجرة بـ JSON.stringify(ast): هل شكلها يطابق ما قصدته؟ إن كان خطأ هنا فالمشكلة في الـ Parser.
  3. تتبّع التقييم: إن كانت الشجرة صحيحة والنتيجة خاطئة فالمشكلة في الـ Interpreter.

أخطاء شائعة

  • تعديل الـ Interpreter لعلاج خطأ سببه الـ Parser: تُصلح العَرَض لا السبب.
  • رسائل خطأ عامة مثل «Error» دون موضع أو توقّع، فتضيع ساعات في البحث.

الخلاصة

  • لكل مرحلة نوع خطأ خاص بها.
  • الرسالة الجيدة تذكر المتوقَّع والموضع.
  • تتبّع المشكلة بفحص ناتج كل مرحلة بالترتيب.

الخطوة التالية: ننفّذ الشجرة فعليًا: المفسّر والمتغيرات.

الفكرة الأساسية

اعرف المرحلة التي رفضت الشيفرة، وافحص ناتج كل مرحلة بالترتيب بدل التخمين.

مثال عملي

شاهد الفكرة في كود

JavaScript 
const tokens = ["(", "1", "+", "2"];
let depth = 0;
for (const t of tokens) {
if (t === "(") depth++;
if (t === ")") depth--;
}
console.log(depth === 0 ? "balanced" : "unbalanced by " + depth);

اكتب checkParens(tokens) تفحص مصفوفة رموز وتعيد { ok: true } إن كانت الأقواس متوازنة، وإلا { ok: false, pos, message } حيث pos فهرس أول خطأ. قوس مغلق زائد: الرسالة Unexpected ')' at pos. قوس مفتوح بلا إغلاق: الرسالة Unclosed '(' at pos وpos فهرس ذلك القوس.
