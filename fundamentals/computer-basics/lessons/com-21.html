استدعاءات النظام والـ Shell

افتح الدرس التفاعلي (محرر + اختبار + تتبّع التقدم)يعمل التمرين والاختبار وحفظ التقدم في الصفحة التفاعلية.

استدعاءات النظام والـ Shell

أهداف الدرس

  • تشرح ما هو System Call وكيف ينتقل البرنامج من User Mode إلى Kernel Mode.
  • تتتبع ما يحدث عند قراءة ملف.
  • تفهم دور الـ Shell.

المتطلبات السابقة

  • درس معمارية نظام التشغيل (com-21).

البوابة الوحيدة إلى النواة

بما أن التطبيقات لا تملك صلاحية التعامل مع العتاد، فهي تطلب كل خدمة عبر System Call: طلب منظّم للنواة، مثل فتح ملف أو إنشاء عملية أو إرسال بيانات على الشبكة. تعليمة خاصة في المعالج تنقل التنفيذ إلى النواة في Kernel Mode، وبعد انتهاء الطلب يعود التنفيذ إلى البرنامج.

مشاهدة الاستدعاءات فعليًا

على Linux تُظهر الأداة strace كل استدعاء ينفذه برنامج. هذا مثال مبسّط لما ينتج عند طباعة محتوى ملف:

الرقم 3 هو File Descriptor: مقبض تعطيه النواة للملف المفتوح. والرقم 1 هو الإخراج القياسي (الشاشة).

الـ Shell

Shell برنامج عادي في User Space يقرأ ما تكتبه، ويطلب من النواة تشغيل البرامج. سطر الأوامر (Bash أو PowerShell) هو Shell نصي، وسطح المكتب الرسومي هو Shell رسومي. لا يوجد شيء سحري فيه: إنه تطبيق مثل غيره.

تمرين لماذا لا يستطيع برنامج تنفيذ تعليمة قراءة القرص مباشرة؟
عرض الحل

لأن تعليمات الإدخال والإخراج محجوزة لـ Kernel Mode. لو سُمح بها لأي برنامج لتجاوز فحص الصلاحيات وقرأ ملفات غيره. النظام يجعل النواة نقطة التحكم الوحيدة.

الخلاصة

  • System Call هو الطريقة المنظمة لطلب خدمة من النواة.
  • الانتقال بين الوضعين تفرضه تعليمة خاصة في المعالج.
  • الـ Shell تطبيق عادي وليس جزءًا من النواة.

الخطوة التالية: ما الفرق بين البرنامج والعملية؟ الدرس القادم.

المفهوم الأساسي

كل ما يفعله تطبيق خارج حدوده، من فتح ملف إلى فتح اتصال، يمر عبر System Call.

تطبيق عملي

جرّب بنفسك

إن كنت على Linux أو macOS جرّب <code>ls -l</code> ثم <code>strace -c ls</code> (أو <code>dtruss</code>) وقارن عدد الاستدعاءات. وإن كنت على Windows فاقرأ عن Process Monitor.

اختبر نفسك

  1. أين تعمل التطبيقات العادية؟

    • User Space بصلاحيات محدودة
    • Kernel Space بصلاحيات كاملة
    • داخل المعالج فقط
    • داخل القرص
    الإجابة والشرح

    الإجابة الصحيحة: User Space بصلاحيات محدودة

  2. لماذا ينهار المتصفح وحده عند وقوع خطأ فيه بينما قد يُسقط خطأ في مشغّل جهاز النظام كله؟

    • المتصفح يعمل في Kernel Space
    • المشغّل يعمل في User Space بلا صلاحيات
    • المتصفح معزول في User Space والمشغّل يعمل بصلاحيات كاملة داخل النواة
    • كلاهما يعمل بالصلاحيات نفسها
    الإجابة والشرح

    الإجابة الصحيحة: المتصفح معزول في User Space والمشغّل يعمل بصلاحيات كاملة داخل النواة

    خطأ في الفضاء الكامل الصلاحيات قد يفسد الذاكرة والعتاد، أما خطأ التطبيق فيُنهى عمليته فقط.

  3. أي نواة تُبقي الحد الأدنى فيها وتشغّل باقي الخدمات كعمليات عادية؟

    • النواة المتراصة
    • النواة الدقيقة
    • لا يوجد هذا النوع
    • نواة المتصفح
    الإجابة والشرح

    الإجابة الصحيحة: النواة الدقيقة

    النواة الدقيقة مثل MINIX وQNX أعزل لكنها أبطأ قليلاً.

  4. أي عبارة تخلط بين النواة ونظام التشغيل؟

    • النواة جزء من نظام التشغيل
    • Ubuntu نواة Linux مع مكتبات وأدوات وسطح مكتب
    • النواة هي نظام التشغيل كله ولا شيء غيرها
    • Linux بالمعنى الدقيق نواة فقط
    الإجابة والشرح

    الإجابة الصحيحة: النواة هي نظام التشغيل كله ولا شيء غيرها

    النواة جزء من النظام وليست كله، فالنظام يشمل المكتبات والأدوات أيضاً.

  5. ماذا يحدث عندما ينفّذ تطبيق في User Mode تعليمة حساسة كتعديل جداول الذاكرة؟

    • تُنفَّذ بصمت
    • يرفضها المعالج ويُطلق استثناءً يعالجه النظام
    • يعيد الحاسوب التشغيل فوراً
    • تُنقل إلى القرص
    الإجابة والشرح

    الإجابة الصحيحة: يرفضها المعالج ويُطلق استثناءً يعالجه النظام

    المعالج نفسه يفرض الفصل بين الأوضاع ويمنع التعليمات الحساسة خارج وضع النواة.
