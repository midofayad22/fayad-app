الأداء والذاكرة

تعقيد الخوارزميات، تجنب التسريبات الشائعة، وقياس الأداء قبل التحسين.

افتح الدرس التفاعلي (محرر + اختبار + تتبّع التقدم)يعمل التمرين والاختبار وحفظ التقدم في الصفحة التفاعلية.

فكّر في التعقيد

البحث في مصفوفة O(n) بينما Set.has وMap.get تقريبًا O(1). استبدال بحث داخل حلقة بـ Set قد يحول O(n²) إلى O(n).

تسريبات الذاكرة الشائعة

  • مستمعو أحداث لم تُزَل.
  • مؤقتات setInterval لم تُلغَ.
  • Closures تمسك بكائنات ضخمة.
  • Maps عامة تكبر بلا حد (استخدم WeakMap أو حدًّا للحجم).

قِس أولًا ثم حسّن. التحسين المبكر دون قياس يضيّع الوقت.

مثال برمجي

كود JavaScript

const N = 2000;
const a = Array.from({ length: N }, (_, i) => i);
const b = Array.from({ length: N }, (_, i) => i * 2);
function slow() {
let n = 0;
for (const x of a) if (b.includes(x)) n++;
return n;
}
function fast() {
const set = new Set(b);
let n = 0;
for (const x of a) if (set.has(x)) n++;
return n;
}
console.log(slow() === fast(), fast());
const cache = new Map();
function remember(key, value, max = 3) {
cache.set(key, value);
if (cache.size > max) cache.delete(cache.keys().next().value);
}
["a", "b", "c", "d", "e"].forEach((k, i) => remember(k, i));
console.log([...cache.keys()]);
true 1000
[ 'c', 'd', 'e' ]

فهم الكود

النسختان تعطيان نفس النتيجة لكن الثانية أسرع كثيرًا مع الأحجام الكبيرة. الـ cache المحدود يحذف أقدم مفتاح (Map تحافظ على ترتيب الإدخال) فلا ينمو بلا حد.

جرّب بنفسك

اكتب دالة تعيد العناصر المشتركة بين مصفوفتين باستخدام <code>Set</code>.

الناتج

اختبر نفسك

  1. ما فائدة Set.has مقارنة بـ includes؟

    • بحث أسرع (تقريبًا ثابت الزمن) في المجموعات الكبيرة
    • تحذف التكرار تلقائيًا من الإخراج
    • تعمل على النصوص فقط
    • لا فرق أبدًا
    الإجابة والشرح

    الإجابة الصحيحة: بحث أسرع (تقريبًا ثابت الزمن) في المجموعات الكبيرة

  2. أي مما يلي سبب شائع لتسرب الذاكرة؟

    • مستمعو أحداث لم تُزَل
    • استخدام const
    • كتابة تعليقات
    • استخدام map
    الإجابة والشرح

    الإجابة الصحيحة: مستمعو أحداث لم تُزَل

  3. ما القاعدة الصحيحة للتحسين؟

    • قِس أولًا ثم حسّن الأبطأ فعلًا
    • حسّن كل سطر مبكرًا
    • لا تحسّن أبدًا
    • اكتب كل شيء بحلقات متداخلة
    الإجابة والشرح

    الإجابة الصحيحة: قِس أولًا ثم حسّن الأبطأ فعلًا

  4. حلقة تكتب style لعنصر ثم تقرأ offsetHeight في كل دورة. ما المشكلة وما الحل؟

    • لا مشكلة، فالقراءة سريعة دائماً
    • التبديل بين الكتابة والقراءة يجبر المتصفح على إعادة حساب التخطيط في كل دورة، فنجمّع القراءات ثم الكتابات
    • offsetHeight لا تعمل داخل الحلقات
    • الحل هو استخدام var بدل let
    الإجابة والشرح

    الإجابة الصحيحة: التبديل بين الكتابة والقراءة يجبر المتصفح على إعادة حساب التخطيط في كل دورة، فنجمّع القراءات ثم الكتابات

    قراءة خاصية تخطيط بعد تعديل مرتبط بها تفرض إعادة حساب متزامنة تسمى layout thrashing. تجميع كل القراءات أولاً ثم الكتابات يجعل المتصفح يحسب مرة واحدة.

  5. قائمة فيها 1000 عنصر يجب أن يستجيب كل منها للنقر. ما الأسلوب الأكفأ؟

    • إضافة مستمع منفصل لكل عنصر
    • استخدام setInterval لفحص النقرات
    • مستمع واحد على الحاوية يفحص event.target (event delegation)
    • إعادة بناء الصفحة بعد كل نقرة
    الإجابة والشرح

    الإجابة الصحيحة: مستمع واحد على الحاوية يفحص event.target (event delegation)

    الأحداث تفقع إلى الحاوية، فمستمع واحد يخدم كل العناصر ويعمل أيضاً مع العناصر المضافة لاحقاً. هذا يوفر ذاكرة ووقتاً مقارنة بألف مستمع.
