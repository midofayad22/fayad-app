Custom Errors

ارثِ من Error وحدد name وخصائص إضافية. استخدم الخيار cause للاحتفاظ بالخطأ الأصلي عند الالتفاف حوله.

أين نلتقط؟

التقط الخطأ حيث تستطيع فعل شيء مفيد به (إعادة محاولة، رسالة للمستخدم)، وإلا اتركه يصعد. لا تبتلع الأخطاء بصمت.

أضف السياق عند إعادة الرمي بدل إخفاء الخطأ الأصلي.

مثال برمجي

كود JavaScript

class ValidationError extends Error {
constructor(field, message, options) {
super(message, options);
this.name = "ValidationError";
this.field = field;
}
}
function parseAge(input) {
const n = Number(input);
if (!Number.isInteger(n) || n < 0) {
throw new ValidationError("age", "invalid age: " + input);
}
return n;
}
function load(input) {
try { return parseAge(input); }
catch (e) { throw new Error("load failed", { cause: e }); }
}
try { load("abc"); }
catch (e) {
console.log(e.message, "|", e.cause.name, e.cause.field);
console.log(e instanceof Error, e.cause instanceof ValidationError);
}
console.log(load("42"));
load failed | ValidationError age
true true
42

فهم الكود

الخطأ المغلّف يحتفظ بالسبب الأصلي في cause فيسهل التتبع. instanceof تتيح التفرقة بين الأنواع داخل catch.

اختبر نفسك

  1. ما فائدة الخيار cause؟

    • حفظ الخطأ الأصلي عند إعادة الرمي
    • إيقاف البرنامج
    • تحويل الخطأ لنص
    • تجاهل الخطأ
    الإجابة والشرح

    الإجابة الصحيحة: حفظ الخطأ الأصلي عند إعادة الرمي

  2. ما أفضل مكان لالتقاط الخطأ؟

    • حيث يمكنك معالجته بشكل مفيد
    • في كل سطر
    • في النطاق العام فقط دائمًا
    • لا تلتقطه أبدًا
    الإجابة والشرح

    الإجابة الصحيحة: حيث يمكنك معالجته بشكل مفيد

  3. لماذا نعرف أنواع أخطاء مخصصة؟

    • للتفرقة بينها بـ instanceof وإضافة بيانات
    • لتسريع الكود
    • لأنها إلزامية
    • لإخفاء الرسائل
    الإجابة والشرح

    الإجابة الصحيحة: للتفرقة بينها بـ instanceof وإضافة بيانات

  4. ما ناتج الكود؟ class MyErr extends Error { constructor(m) { super(m); this.name = "MyErr"; } } const e = new MyErr("x"); console.log(e instanceof Error, String(e));

    • false و Error: x
    • true و Error: x
    • true و MyErr: x
    • true و x
    الإجابة والشرح

    الإجابة الصحيحة: true و MyErr: x

    الكلاس يمتد من Error فهو instanceof Error، و String يستخدم name و message فيعطي MyErr: x. لو لم نضبط name لظهر Error: x.

  5. أي أسلوب أفضل في catch عندما لا نعرف نوع الخطأ؟

    • ابتلاع الخطأ بكتلة catch فارغة حتى لا يتوقف البرنامج
    • التحقق من النوع بـ instanceof والتعامل مع المعروف وإعادة رمي غير المعروف
    • تحويل كل الأخطاء إلى رسالة نصية عامة
    • طباعة الخطأ فقط ثم المتابعة كأن شيئاً لم يحدث
    الإجابة والشرح

    الإجابة الصحيحة: التحقق من النوع بـ instanceof والتعامل مع المعروف وإعادة رمي غير المعروف

    نعالج الأخطاء التي نفهمها ونعرف كيف نتعافى منها، ونعيد رمي الباقي ليصل إلى مستوى أعلى يتعامل معه. ابتلاعها يخفي العلل الحقيقية ويصعّب اكتشافها.
