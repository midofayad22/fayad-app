اربط أجزاء التطبيق بدون اعتماد مباشر بينها بأنماط الأحداث.

افتح الدرس التفاعلي (محرر + اختبار + تتبّع التقدم)يعمل التمرين والاختبار وحفظ التقدم في الصفحة التفاعلية.

Observer / Pub-Sub

ينشر المصدر (Subject) أحداثًا ويشترك فيها مستمعون دون أن يعرف المصدر من هم. هذا يقلل الاقتران ويسهل الاختبار والتوسع.

احذر التسرب

كل اشتراك يجب أن يكون له إلغاء (unsubscribe)، وإلا بقيت المراجع في الذاكرة.

كل subscribe يُرجع دالة إلغاء الاشتراك.

مثال برمجي

كود JavaScript

function createStore(initial) {
let state = initial;
const listeners = new Set();
return {
get: () => state,
set(next) {
state = { ...state, ...next };
listeners.forEach((fn) => fn(state));
},
subscribe(fn) {
listeners.add(fn);
return () => listeners.delete(fn);
},
};
}
const store = createStore({ count: 0 });
const off = store.subscribe((s) => console.log("A sees", s.count));
store.subscribe((s) => console.log("B sees", s.count));
store.set({ count: 1 });
off();
store.set({ count: 2 });
A sees 1
B sees 1
B sees 2

فهم الكود

بعد استدعاء off() لم يعد المشترك A يتلقى التحديثات. استخدام Set يمنع تسجيل نفس الدالة مرتين.

اختبر نفسك

  1. ما الميزة الأساسية لنمط Pub/Sub؟

    • تقليل الاقتران بين الناشر والمستمعين
    • تسريع الشبكة
    • تشفير البيانات
    • إلغاء الأخطاء
    الإجابة والشرح

    الإجابة الصحيحة: تقليل الاقتران بين الناشر والمستمعين

  2. لماذا نرجع دالة من subscribe؟

    • لإلغاء الاشتراك ومنع تسرب الذاكرة
    • لطباعة النتيجة
    • لتكرار الحدث
    • لتغيير الحالة
    الإجابة والشرح

    الإجابة الصحيحة: لإلغاء الاشتراك ومنع تسرب الذاكرة

  3. لماذا نستخدم Set لتخزين المستمعين؟

    • لمنع تكرار نفس المستمع وسهولة الحذف
    • لأن Array غير موجودة
    • لتشفيرهم
    • لترتيبهم أبجديًا
    الإجابة والشرح

    الإجابة الصحيحة: لمنع تكرار نفس المستمع وسهولة الحذف

  4. ما ناتج الكود؟ const s = new Set(); const l = () => console.log("x"); s.add(l); s.add(l); s.forEach(f => f());

    • x مرة واحدة لأن Set لا تكرر العنصر نفسه
    • x مرتين
    • لا شيء
    • خطأ عند الإضافة الثانية
    الإجابة والشرح

    الإجابة الصحيحة: x مرة واحدة لأن Set لا تكرر العنصر نفسه

    المستمع المسجل مرتين هو الدالة نفسها، و Set تحتفظ بنسخة واحدة منها، فلا يُنفَّذ المستمع مرتين لنفس الحدث. هذا سبب اختيارها لتخزين المشتركين.

  5. مكوّن واجهة اشترك في حدث عام ثم أُزيل من الصفحة دون إلغاء الاشتراك. ما النتيجة؟

    • يلغى الاشتراك تلقائياً عند إزالة المكوّن
    • تتجاهل المنصة الحدث
    • يبقى callback مسجلاً فيعمل على مكوّن ميت ويمنع تحرير ذاكرته
    • يرمي الحدث خطأ في كل مرة
    الإجابة والشرح

    الإجابة الصحيحة: يبقى callback مسجلاً فيعمل على مكوّن ميت ويمنع تحرير ذاكرته

    الناشر يحتفظ بمرجع إلى callback ومعه كل ما التقطه من المكوّن، فلا يستطيع GC تحريرها ويستمر تنفيذها. لذلك نستدعي دالة unsubscribe عند التنظيف.
