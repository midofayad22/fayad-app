حالات التحميل والأخطاء

تعلم كيف تعرض واجهة مناسبة أثناء تحميل البيانات أو عند حدوث خطأ.

افتح الدرس التفاعلي (محرر + اختبار + تتبّع التقدم)يعمل التمرين والاختبار وحفظ التقدم في الصفحة التفاعلية.

عند جلب البيانات من API قد يحتاج التطبيق بعض الوقت قبل وصول النتيجة.

لذلك من الأفضل إظهار Loading state حتى يعرف المستخدم أن العملية ما زالت مستمرة.

وفي حالة فشل الطلب يجب إظهار Error state مناسبة بدل ترك المستخدم دون أي معلومات.

Loading وError states جزء أساسي من تجربة المستخدم الجيدة.

مثال برمجي

الكود

if (loading) {
return <p>جارٍ التحميل...</p>;
}
if (error) {
return <p>حدث خطأ.</p>;
}

فهم الكود

التطبيق الاحترافي لا يعرض البيانات فقط، بل يتعامل أيضًا مع حالات الانتظار والفشل.

غيّر رسائل Loading وError.

اختبر نفسك

  1. لماذا نستخدم Loading state؟

    • لإخبار المستخدم أن البيانات ما زالت تُحمّل
    • لتغيير CSS
    • لحذف Component
    • لإنشاء Database
    الإجابة والشرح

    الإجابة الصحيحة: لإخبار المستخدم أن البيانات ما زالت تُحمّل

  2. متى نستخدم Error state؟

    • عند حدوث مشكلة في العملية
    • عند نجاح الطلب فقط
    • عند تغيير اللون
    • عند تحميل CSS
    الإجابة والشرح

    الإجابة الصحيحة: عند حدوث مشكلة في العملية

  3. ما الفائدة الأساسية من هذه الحالات؟

    • تحسين تجربة المستخدم
    • حذف JavaScript
    • إلغاء APIs
    • إلغاء State
    الإجابة والشرح

    الإجابة الصحيحة: تحسين تجربة المستخدم

  4. أي ترتيب لفحوص العرض صحيح؟

    • return <List/> دائماً
    • عرض Err قبل بدء الطلب
    • إخفاء كل شيء
    • if (loading) return <Spinner/>; if (error) return <Err/>; return <List/>
    الإجابة والشرح

    الإجابة الصحيحة: if (loading) return <Spinner/>; if (error) return <Err/>; return <List/>

    نعالج التحميل ثم الخطأ ثم النجاح.

  5. ماذا يحدث إن لم نضف catch أو فحص res.ok؟

    • يُصلح الخادم نفسه
    • لا يتغير شيء أبداً
    • قد تبقى الشاشة بحالة تحميل أو تعرض بيانات خاطئة
    • يصبح الطلب أسرع
